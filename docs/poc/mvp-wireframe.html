Kyle · 방금
상황

선택

결정
메시지는 항상 엔터로 줄바꿈
Kyle · 20일 전
상황
메시지 입력 시 줄바꿈·전송 단축키를 어떻게 배정할지 정해야 했다.
선택
엔터는 항상 줄바꿈으로 쓰고, 전송은 별도 버튼이나 다른 단축키로 한다.
이유
기존 메신저 관례와 맞추는 게 익숙할 거라 판단했다.
마케팅팀 정기 싱크
저는 심플한 의견을 보긴 했어요. 수신함은 확실히 내부 대화든 뭐든 커맨드 멘터가 기본인 게 좋긴 하겠다. 대 고객이니까 되게 실수하는 리스크가 크잖아요. 팀 내부는 아닐 수 있겠다. 그냥 스페이스로 분리하면 안 되나? 그러면 이렇게 하시죠. 인라인 모드는 일단 만들지 말고 이번에 코멘트 엔터를 전송으로 기본으로 바꿔서 출시를 해봅시다. 그다음에 고객 피드백 듣고 좀 불편하다라니면 이게 의견을 듣는 걸로 그리고 도치 옵션을 제공하자라는 커맨드 터가 가동이 아니라 엔터 전송으로 하고 싶다 하면은 설정을 제공한다.
이메일 UX 정책 리뷰
이메일 쪽 발신자 표시를 어떻게 할지 정해야 하는데요. 저는 아바타랑 이름을 항상 보여주는 쪽이 낫다고 봐요. 고객 입장에서 지금 누구랑 얘기하고 있는지 바로 보여야 신뢰가 생기잖아요. 그래서 이번엔 그렇게 기본값으로 가는 걸로 정리하겠습니다.
발신자 정보 표시 간소화 논의
최근에 이메일 UI가 너무 무겁다는 피드백이 계속 들어오고 있어서요, 발신자 쪽부터 좀 걷어내볼까 하는데. 아바타랑 이름 표시는 빼고 그냥 이메일 주소만 보여주는 식으로 가면 훨씬 간결해질 것 같아요. 일단 이렇게 정리해서 이번 배포에 반영하시죠.

상황
메시지 입력 시 줄바꿈(엔터)과 전송(커맨드+엔터) 단축키를 어떻게 배정할지, 인라인 편집 모드 도입 여부와 함께 검토가 필요했다
선택
인라인 모드는 이번엔 만들지 않고, 커맨드+엔터 전송을 기본값으로 출시. 이후 설정에서 엔터 전송으로 바꿀 수 있는 옵션을 제공한다
이유
고객 대면 채널은 오전송 리스크가 커서, 커맨드+엔터가 기본인 게 더 안전하다고 판단. 초기 피드백에서도 이 방향에 대한 불만이 없었음
트레이드오프
팀 내부 스페이스에서는 오히려 엔터 전송이 더 빠르고 편할 수 있음
