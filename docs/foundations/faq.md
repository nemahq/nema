# 예상 반론

네마가 받을 적대적 질문과 그 답을 모은다. 자화자찬이 아니라, 공격을 어떻게 막는지를 정리하는 문서다.

## "그냥 GitHub에 맥락 저장하고 LLM과 쓰면 되지 않나?"

GitHub + LLM은 거의 공짜고 이미 존재한다. 네마가 그것과 본질적으로 다르지 않으면 존재 이유가 없다. 정면으로 답한다.

**핵심 — GitHub는 텍스트의 버전관리지, 의미의 버전관리가 아니다.**

맥락에 필요한 동작을 GitHub로 해보면 하나씩 깨진다.

- **합치기** — "팀 옮겼다"와 "이직했다"가 같은 의미인 걸 git은 모른다. git의 diff/merge는 텍스트 줄 비교라, 의미가 같아도 다른 줄이면 별개다. 중복이 그대로 쌓인다.
- **충돌 드러내기** — git 충돌은 "같은 줄을 동시에 고쳤을 때"만 뜬다. "A는 X다"와 "A는 X 아니다"가 다른 파일에 있으면 충돌로 보지 않는다. 의미적 모순을 못 잡는다.
- **유효성** — "이 결정은 3월엔 맞았지만 지금 폐기됨"을 git은 모른다. git은 최신 커밋이 곧 진실이라, 시간에 묶인 유효성 개념이 없다.
- **찾기** — git 검색은 단어 일치(grep)다. "왜 토스 썼지?"를 의미로 못 찾는다.

git의 diff·merge·blame은 의미를 모르는 텍스트 알고리즘이다. 코드는 텍스트라 그것으로 충분했지만, 맥락은 의미라서 같은 동작을 하려면 의미를 읽어야 한다. GitHub엔 그 엔진이 없다.

**"그럼 LLM이 읽어주면 되잖아?" — 여기가 갈림이다.**

LLM은 상태가 없다(stateless). 매번 처음부터 다 읽어야 한다. GitHub에 맥락 1만 개가 텍스트로 쌓여 있을 때 "새로 들어온 것과 충돌하는 게 있나?"를 물으려면 1만 개를 매번 다 떠먹여야 한다 — 비싸고 느리고, 컨텍스트 한계를 넘으면 아예 못 한다.

네마가 만드는 것은 그 사이의 **구조**다. 진술이 이미 관계로 연결돼 있고 확신도가 이미 붙어 있어서, LLM은 관련된 몇 개만 꺼내 보면 된다. GitHub+LLM은 매번 전체를 재계산하고, 네마는 구조에 누적한다.

**한 줄.** 네마가 만드는 건 LLM이 아니라, LLM이 매번 다시 안 읽어도 되게 하는 그 밑의 구조(진술 + 관계 + 속성)다. GitHub는 그 구조를 주지 않는다.

> 주의: 이 답은 "기술적으로 왜 다른가"까지다. "왜 *우리*가 이기나"는 별도다(전략 문서의 해자 — 사람 주권·관계·중립).
