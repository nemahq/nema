### 케이스 상세

#### 구글 로그인

- **Given**: 유저가 비로그인 상태로 로그인 화면에 있다.
- **When**: 구글 로그인 액션을 실행하고 Google 인증을 완료한다.
- **Then**:
  1. 인증 성공 상태가 된다.
  2. 유저의 첫 진입 여부에 따라 "신규 유저 최초 로그인" 또는 "기존 유저 로그인" 케이스로 이어진다.
- **관여 화면**: 로그인

#### 구글 로그인 취소·거부

- **Given**: 유저가 로그인 화면에서 구글 로그인 액션을 실행해 Google 인증 화면으로 이동했다.
- **When**: Google 인증 화면에서 동의를 거부하거나 절차를 취소한다.
- **Then**:
  1. 로그인 화면으로 돌아온다.
  2. 별도 실패 안내 없이 로그인 폼 상태로 복귀한다(유저가 스스로 취소한 정상 종료로 취급).
  3. 세션은 생성되지 않고 비로그인 상태가 유지된다.
- **관여 화면**: 로그인

#### 구글 로그인 기술적 실패

- **Given**: 유저가 로그인 화면에서 구글 로그인 액션을 실행한다.
- **When**: 네트워크 오류, 설정 오류 등으로 구글 인증 요청 자체가 실패한다.
- **Then**:
  1. 로그인 화면에 머무른다.
  2. 인증이 실패했다는 안내가 표시된다.
  3. 세션은 생성되지 않고 비로그인 상태가 유지된다.
- **관여 화면**: 로그인

#### 이메일 매직링크 로그인

- **Given**: 유저가 비로그인 상태로 로그인 화면에 있다.
- **When**: 이메일 주소를 입력하고 이메일 매직링크 로그인 액션을 실행한다.
- **Then**:
  1. 매직링크 이메일이 발송된다.
  2. 화면은 메일 확인 대기 상태로 전환된다(발송한 이메일 주소 표시, 로그인 폼으로 되돌아가는 액션 제공).
  3. 유저가 메일 속 링크를 클릭하면 인증 성공 상태가 된다.
  4. 첫 진입 여부에 따라 "신규 유저 최초 로그인" 또는 "기존 유저 로그인" 케이스로 이어진다.
- **관여 화면**: 로그인

#### 이메일 형식 오류

- **Given**: 유저가 비로그인 상태로 로그인 화면에 있다.
- **When**: 형식에 맞지 않는 값을 이메일 입력란에 넣고 이메일 매직링크 로그인 액션을 실행한다.
- **Then**:
  1. 매직링크가 발송되지 않는다.
  2. 유효한 이메일 형식이 아니라는 안내가 표시된다.
  3. 화면은 로그인 폼 상태를 유지한다.
- **관여 화면**: 로그인

#### 매직링크 만료·재사용 오류

- **Given**: 유저가 유효기간이 지났거나 이미 사용된 매직링크를 가지고 있다.
- **When**: 그 링크로 접근한다.
- **Then**:
  1. 인증되지 않는다.
  2. 링크가 유효하지 않다는 안내와 함께 로그인 화면으로 이동한다.
- **관여 화면**: 로그인

#### 신규 유저 최초 로그인 (첫 진입)

- **Given**: 유저가 처음으로 인증에 성공했고, 이 로그인이 이 유저의 첫 진입이다(가입 트리거가 만든 기본 Space는 이미 있지만, 이 유저는 아직 한 번도 앱에 들어온 적이 없다).
- **When**: 인증이 완료되어 앱 진입이 트리거된다.
- **Then**: 그 기본 Space의 오버뷰 화면으로 이동한다.
- **관여 화면**: 로그인, Space 오버뷰

#### 기존 유저 로그인 (첫 진입 아님)

- **Given**: 유저가 인증에 성공했고, 이 로그인은 이 유저의 첫 진입이 아니다(이전에 이미 로그인한 적이 있다).
- **When**: 인증이 완료되어 앱 진입이 트리거된다.
- **Then**:
  1. 새 Space를 만들지 않는다.
  2. Space 개수와 무관하게 항상 홈으로 이동한다(마지막 활성 Space를 기억해 그리로 보내지 않음).
- **관여 화면**: 로그인, 홈

#### 이미 로그인된 상태로 재방문

- **Given**: 유저가 유효한 세션을 가진 채로(이미 인증된 상태), 목적지 없이 로그인 화면(또는 루트 경로)에 접근한다.
- **When**: 해당 경로에 접근한다.
- **Then**:
  1. 로그인 폼을 보여주지 않는다.
  2. "신규/기존 유저 로그인" 케이스의 진입 로직을 그대로 따라 즉시 이동한다(신규는 자기 Space로, 기존은 홈으로).
- **관여 화면**: 로그인, 홈, Space 오버뷰

#### 비로그인 상태에서 보호된 화면 접근

- **Given**: 유저가 비로그인 상태이고, 인증이 필요한 특정 화면(예: 특정 Digest 상세 링크)에 접근하려 한다.
- **When**: 그 화면의 URL로 접근한다.
- **Then**:
  1. 로그인 화면으로 이동한다.
  2. 로그인에 성공하면 Space 오버뷰가 아니라 원래 접근하려던 화면으로 복귀한다.
- **관여 화면**: 로그인, (접근하려던 원래 화면)

### 케이스 상세

#### Space 생성

- **Given**: 유저가 LNB에서 Space 목록을 보고 있고, 현재 Space에 열려 있는 사이드뷰(Digest 상세 등) 탭이 있을 수 있다.
- **When**: 새 Space 생성 액션을 실행해 모달에 이름을 입력하고 생성한다.
- **Then**:
  1. 새 Space가 생성된다.
  2. 그 Space로 즉시 전환되어 Space 오버뷰로 이동한다.
  3. 이전 Space에서 열려 있던 사이드뷰 탭은 모두 닫힌다.
- **관여 화면**: LNB, Space 설정 모달, Space 오버뷰
- **범위 참고 (2026-07-10)**: 사이드뷰 탭 시스템 자체가 아직 이 앱에 구현돼 있지 않다(다른 화면 그룹의 몫). 이번 슬라이스에서 실제로 구현·검증한 건 1·2번(생성 후 즉시 그 Space로 전환)뿐이고, 3번은 사이드뷰가 생기는 후속 슬라이스에서 함께 검증한다.

#### Space 이름 미입력

- **Given**: 유저가 Space 설정 모달을 생성 목적으로 열었다.
- **When**: 이름을 입력하지 않고 생성 액션을 실행한다.
- **Then**:
  1. 생성되지 않는다.
  2. 이름 입력이 필요하다는 안내가 표시된다.
- **관여 화면**: Space 설정 모달

#### Space 생성 취소

- **Given**: 유저가 Space 설정 모달을 생성 목적으로 열었다.
- **When**: 취소 액션을 실행하거나 모달을 닫는다.
- **Then**:
  1. Space가 생성되지 않는다.
  2. 모달이 닫힌다.
  3. 원래 있던 Space와 화면 상태가 그대로 유지된다.
- **관여 화면**: Space 설정 모달

#### Space 이름 중복 오류

- **Given**: 유저가 속한 Workspace에 이미 특정 이름의 Space가 존재한다.
- **When**: 같은 이름으로 새 Space 생성 액션을 실행한다.
- **Then**:
  1. 생성되지 않는다.
  2. 이미 사용 중인 이름이라는 안내가 표시된다.
- **관여 화면**: Space 설정 모달

#### Space 이름 변경

- **Given**: 유저가 자신이 속한 Space들 중 하나를 보고 있고, 변경하려는 새 이름은 같은 Workspace 안에서 중복되지 않는다.
- **When**: 그 Space의 이름 변경 액션을 실행하고 새 이름을 입력해 저장한다.
- **Then**: Space 이름이 변경한 이름으로 즉시 반영된다.
- **관여 화면**: LNB, Space 설정 모달

#### Space 이름 변경 시 중복 오류

- **Given**: 유저가 자신이 속한 Space들 중 하나를 보고 있고, 변경하려는 새 이름은 같은 Workspace 안에서 다른 Space가 이미 쓰고 있다.
- **When**: 그 Space의 이름 변경 액션을 실행하고 그 이름으로 저장을 시도한다.
- **Then**:
  1. 변경이 거부된다.
  2. 이미 사용 중인 이름이라는 안내가 표시된다.
- **관여 화면**: LNB, Space 설정 모달

#### Space 전환

- **Given**: 유저가 Space A에 있고, 그 Space에 열려 있는 사이드뷰 탭이 있을 수 있다.
- **When**: LNB에서 기존 Space B를 클릭한다.
- **Then**:
  1. Space B의 오버뷰로 이동한다.
  2. Space A에서 열려 있던 사이드뷰 탭은 모두 닫힌다.
- **관여 화면**: LNB, Space 오버뷰
- **범위 참고 (2026-07-10)**: 사이드뷰 탭 시스템 자체가 아직 이 앱에 구현돼 있지 않다(다른 화면 그룹의 몫). 이번 슬라이스에서 실제로 구현·검증한 건 1번(전환 시 오버뷰 이동)뿐이고, 2번은 사이드뷰가 생기는 후속 슬라이스에서 함께 검증한다.

#### Space 삭제

- **Given**: 유저가 자신이 속한 Workspace에 Space가 2개 이상 있고, 그중 하나를 보고 있다.
- **When**: 그 Space의 삭제 액션을 실행해 다이얼로그에서 Space 이름을 그대로 타이핑해 확인한다.
- **Then**:
  1. 그 Space와 그에 속한 콘텐츠가 삭제된다.
  2. 홈으로 이동한다.
- **관여 화면**: LNB, Space 오버뷰, 홈
- **확정 (2026-07-10)**: 확인 강도는 버튼 클릭이 아니라 **이름 타이핑 확인**(입력값이 Space 이름과 정확히 일치해야 삭제 버튼 활성화) — 콘텐츠가 통째로 사라지는 되돌릴 수 없는 삭제라 세션 삭제보다 강한 확인이 필요하다고 판단. 삭제 후 이동 대상은 "다른 Space의 오버뷰"가 아니라 **홈(`/`)** — 이 판단은 직전 세션(2026-07-10, 신규 유저 랜딩 슬라이스)이 "새 LNB에는 홈 항목을 의도적으로 빼뒀다(홈이 아직 옛 사이드바 셸이라 새 LNB에서 누르면 셸이 통째로 바뀌는 어색함)"고 남긴 결정과 정면으로 충돌한다는 점을 인지한 채로, 그 트레이드오프보다 "삭제 후 어디로든 남은 Space를 골라 보내는 것"의 자의성을 피하는 쪽을 우선한 의도적 선택이다(셸 전환의 어색함은 감수). 딸린 콘텐츠 개수 안내("Digest N·Source M 사라짐")는 **이번 슬라이스엔 없음** — BE 계약(`space.list`/`space.delete`, `workspace.bootstrap`)에 per-space 콘텐츠 개수가 전혀 없어, 이번엔 개수 없는 일반 경고 문구로 대체하고 개수 계약은 후속 BE 작업으로 남겨둔다(design-decisions-log 참고).

#### 마지막 Space 삭제 차단

- **Given**: 유저가 속한 Workspace에 Space가 하나뿐이다.
- **When**: 그 마지막 Space의 삭제를 시도한다.
- **Then**:
  1. 삭제가 차단된다(Workspace는 항상 Space를 최소 1개 유지).
  2. 마지막 Space는 지울 수 없다는 안내가 표시된다.
- **관여 화면**: LNB, Space 오버뷰
- **확정 (2026-07-10)**: "최소 1개 강제"를 그대로 확정했다 — 0개 상태는 bootstrap 자동생성 안전망이 없어지는 이번 슬라이스부터는 되살릴 방법이 없는 사실상의 불변식 위반이 되고, 진짜 "Space 없는 상태"는 계정·워크스페이스 삭제라는 별도 경로로 이미 존재한다. BE도 동일 규칙을 거부하지만(`DB_SPACE_MIN_ONE`) FE가 먼저 막는다.

### 케이스 상세

#### 로그아웃

- **Given**: 유저가 인증된 상태로 계정 설정을 열어보고 있다.
- **When**: 로그아웃 액션을 실행한다.
- **Then**:
  1. 세션이 종료된다.
  2. 로그인 화면으로 이동한다.
- **관여 화면**: 계정 설정, 로그인

#### UI 언어 변경

- **Given**: 유저가 설정 모달(일반 섹션)을 열어보고 있다.
- **When**: UI 언어 변경 액션을 실행해 다른 언어를 선택한다.
- **Then**:
  1. 화면의 UI 텍스트가 선택한 언어로 즉시 바뀐다.
  2. 이 설정은 다음 방문에도 유지된다.
- **관여 화면**: 설정 모달

#### Theme 변경

- **Given**: 유저가 설정 모달(일반 섹션)을 열어보고 있다.
- **When**: Theme 변경 액션을 실행해 다른 모드(라이트/다크/시스템)를 선택한다.
- **Then**:
  1. 화면 전체가 선택한 테마로 즉시 바뀐다.
  2. 이 설정은 다음 방문에도 유지된다.
- **관여 화면**: 설정 모달

#### 계정 삭제 (유일 멤버 워크스페이스)

- **Given**: 유저가 속한 모든 워크스페이스에서 자신이 유일한 멤버다.
- **When**: 계정 삭제 액션을 실행하고 확인한다.
- **Then**:
  1. 그 워크스페이스들은 모두 완전히 삭제된다.
  2. 계정도 삭제된다.
  3. 로그아웃 상태가 된다.
- **관여 화면**: 설정 모달, 로그인

#### 계정 삭제 (다른 멤버 있는 워크스페이스)

- **Given**: 유저가 다른 멤버가 있는 워크스페이스에 속해 있고(자신이 유일한 소유자는 아님), 소유권 이전이 필요한 워크스페이스는 없다.
- **When**: 계정 삭제 액션을 실행하고 확인한다.
- **Then**:
  1. 그 워크스페이스는 유지된 채 이 유저만 멤버십에서 제거된다.
  2. 계정은 삭제된다.
  3. 로그아웃 상태가 된다.
- **관여 화면**: 설정 모달, 로그인

#### 계정 삭제 차단 (소유권 이전 필요)

- **Given**: 유저가 다른 멤버가 있는 워크스페이스에서 유일한 소유자(owner)다.
- **When**: 설정 모달(계정 섹션)의 계정 삭제 화면에 진입한다.
- **Then**:
  1. 삭제 액션을 실행하기 전에, 소유권 이전이 필요한 워크스페이스 목록이 먼저 안내된다.
  2. 이 상태에서 삭제를 시도해도 진행되지 않는다.
- **관여 화면**: 설정 모달

#### 계정 삭제 취소

- **Given**: 유저가 계정 삭제 액션을 실행해 확인 단계에 있다.
- **When**: 취소 액션을 실행한다.
- **Then**:
  1. 계정이 삭제되지 않는다.
  2. 설정 모달(계정 섹션)으로 돌아간다.
- **관여 화면**: 설정 모달

#### MCP 연결 승인

- **Given**: 유저가 외부 MCP 클라이언트로부터 연결 요청을 받아 OAuth 동의 화면에 있다.
- **When**: 접근 허용 액션을 실행한다.
- **Then**:
  1. 그 클라이언트가 연결 목록에 추가된다.
  2. 이후 Space의 Context에 접근할 수 있게 된다.
- **관여 화면**: OAuth 동의 화면

#### MCP 연결 거부

- **Given**: 유저가 외부 MCP 클라이언트로부터 연결 요청을 받아 OAuth 동의 화면에 있다.
- **When**: 접근 거부 액션을 실행한다.
- **Then**:
  1. 연결이 성립되지 않는다.
  2. 그 클라이언트는 연결 목록에 추가되지 않는다.
- **관여 화면**: OAuth 동의 화면

#### MCP 연결 해제

- **Given**: 유저가 설정 모달(MCP 연결 섹션)에서 연결된 MCP 클라이언트 목록을 보고 있다.
- **When**: 특정 연결의 해제 액션을 실행한다.
- **Then**:
  1. 그 연결이 즉시 해제되어 목록에서 제거된다.
  2. 이후 그 클라이언트는 Space의 Context에 접근할 수 없다.
- **관여 화면**: 설정 모달
