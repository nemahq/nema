### 이번 라운드 범위 (2026-08-06 스코프 재정의)

증명 대상을 한 문장으로 좁혔다 — **"이미 쌓인 것을 알아야만 가능한 정리"를 해준다.** 어떤 케이스를 넣을지 헷갈리면 *"이건 쌓인 걸 몰라도 되는 일인가?"*만 물으면 된다.

여기서 따라온 큰 변화 넷:

1. **넣은 직후의 확인 게이트를 없앤다.** 던지면 사람 확인 없이 바로 정리되어 저장된다. 사람이 판정하는 자리는 넣는 시점이 아니라 기존 것과 대조가 끝난 뒤(충돌·중복)다.
2. **사람이 쥐는 것은 판정·빼기·되돌리기 셋뿐이다.** 확정 전·후의 내용 편집은 다음 라운드로 미룬다.
3. **사용자가 배우는 개념은 셋이다** — 다이제스트·주제·레퍼런스. 진술·관계·변경셋·태그는 화면에 안 드러난다. Space는 하나로 고정하고 화면에서 뺀다.
4. **쌓인 것을 보는 자리는 주제 목록**이다. 오랜만에 다시 켠 사람이 "어디까지 왔는지"를 보는 곳이고, Nema가 상태를 요약해 써주지 않는다.

뺀 케이스는 문서마다 표시 방식이 다르다. 개별 케이스 단위로 빠진 곳(둘러보기·계정)은 **문서 하단 "이번 범위 밖" 섹션**에 모았고, 섹션이 통째로 빠진 곳(리뷰의 Ingestion 리뷰·실행취소·Manual 편집, 꺼내기 전체)은 **그 섹션 머리에 인용구로** 표시했다.

하단 섹션은 두 갈래다. 전제가 그대로이고 시점만 미룬 것은 본문까지 남기고, 이번 결정으로 본문이 틀려진 것은 이름과 이유만 남긴다 — 틀린 Given/Then이 남아 있으면 나중에 그대로 만들어질 수 있어서다.

### 시나리오 템플릿

각 플로우 문서의 시나리오는 다음 형식을 따른다:

- **Given** — 전제조건
- **When** — 트리거(사용자 행동)
- **Then** — 기대 결과 (확인 가능한 조건문 — QA 체크리스트로 그대로 재사용). 결과가 2개 이상이면 번호 매긴 목록으로 쓴다. 결과가 1개뿐이면 한 문장으로 둔다
- **관여 화면** — surface-inventory 화면명 참조 (화면 자체의 생김새는 서술하지 않음)
