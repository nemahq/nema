# MVP 엔진 동작 규칙

원문이 들어와 쌓이고 유지되기까지, Nema MVP 엔진이 무엇을 어떤 규칙으로 결정하는지 정한다.

이 엔진이 증명할 것은 하나다. 이미 쌓인 것을 알아야만 가능한 정리를 해준다는 것.

일을 하는 쪽은 셋이다. **[사용자]**, **[코드]**, **[LLM]**. 사람이 누르는 것과 LLM이 하는 것 말고는 전부 코드다.

**LLM은 준 것 안에서만 일한다.** 앞에 놓인 재료를 다듬고 가르는 데까지다. 없는 것을 지어내지 않고, 무엇을 언제 할지 고르지 않고, 어느 쪽이 옳은지 정하지 않는다. 순서는 코드가 쥐고, 옳고 그름은 사람이 쥔다. 아래 규칙 상당수가 이 한 줄에서 나왔고, 새 규칙을 정할 때도 "이건 준 것 안인가"부터 묻는다.

## 이 문서에서 쓰는 말

용어 사전을 따르되, 헷갈리기 쉬운 것만 여기서 고정한다.

| 뜻 | 쓸 말 | 안 쓸 말 |
|---|---|---|
| LLM이 두 다이제스트의 사이를 가르는 일 | 판정 | 리뷰 |
| 사람이 그 결과를 확정하거나 반려하는 일, 그리고 그 한 건 | 리뷰 | 판정 |
| 엔진이 리뷰에 올린 쪽 | 제안 | 판정 |
| 무슨 일이 있었는지 남는 것 | 변경 이력 | 판정 기록 |
| 다이제스트가 담고 있는 것 | 판단 | 판정 |
| 레퍼런스가 기존 것과 같은지 가리는 일 | 맞추기 | 판정, 판단 |

**판정과 리뷰를 가르는 건 주체다.** 엔진이 가르고 사람이 정한다. 낱말만 봐도 누구 얘기인지 읽히게 한다.

**변경 이력은 아직 잠정이다.** 사람이 고른 것과 엔진이 조용히 이은 것이 다 들어가야 해서 리뷰 기록이라 부를 수 없고, `07-modeling.md`의 변경셋과 같은 것인지는 3장에서 정한다.

## 07-modeling에서 아직 안 맞는 것

진술·관계 정의는 `07-modeling.md`가 이미 SSOT다(진술은 테이블 없이 개념만 남고,
관계는 다이제스트끼리 잇는다). 아직 안 맞는 건 07-modeling의 Changeset "동작 규칙"
절이다. Changeset 자체가 이번 라운드에 안 만들어져서, 그 절은 진술 단위
리뷰·되돌리기를 전제로 한 옛 문장을 그대로 갖고 있다. Changeset을 실제로 만들 때
다이제스트 단위로 다시 읽을 것.

- **확정 게이트가 없다.** 정리가 끝나면 사람 확인 없이 저장된다
- **아무것도 안 접는다.** 지지·약화·중복·충돌 넷 다 사람의 리뷰·확정·병합·되돌리기가
  아직 없다(engine/linking.md 2.3 참고). 07-modeling의 changeset 관련 동작 규칙은
  이게 결정되고 Changeset이 만들어질 때를 대비한 설계로 남아 있다
- **관계 유형은 지지·약화·중복·충돌·해소 다섯이다.** 해소는 아직 안 만들었다

## 아직 안 정한 것

- 완료 신호 둘이 언제 켜지고 꺼질지. 정리가 끝났을 때와 연결이 끝났을 때가 사용자에게 다른 것을 뜻한다. 앞은 볼 것이 생겼다는 뜻이고 뒤는 정할 것이 생겼을 수 있다는 뜻이다. 신호가 붙는 단위가 원문인지 다이제스트인지도 함께 정한다
- 좁혀온 기존 레퍼런스가 하나도 없거나 여럿일 때 어떻게 고를지. 후보 유형과 기존 유형이 갈리는 경우("토스"를 조직으로 봤는데 기존은 제품)도 여기서 함께 정한다
- 레퍼런스 쪽 좁히기 상한을 무엇으로 얼마로 둘지. 개수인지 유사도 점수인지, 아니면 둘 다인지(레퍼런스 자체가 아직 안 만들어짐). 관계 쪽은 지금 값(문턱 0.2·후보 상한 5, 갈래 안 나눔)이 잠정으로 정해져 있고, 도그푸딩으로 쌓이면 갈래별로 다시 본다(engine/linking.md 2.3 참고)
- 약화됨을 다이제스트 본문 위 상태로 올릴지. 지금은 관련 목록에만 뜬다. 본문 위 자리를 접힌 것 하나로 좁혀두려고 미뤘는데, 약화가 실제로 잘 잡히는 게 확인되면 그때 본다
- 제목을 원문에만 박을지, 변경셋에도 따로 박을지. 되돌린 뒤 다시 정리하면 제목이 새로 뽑히는데, 옛 변경셋이 그 시점의 이름을 지키려면 자기 제목이 있어야 한다

## 화면 기획으로 넘긴 것

이 문서는 엔진이 무엇을 어떤 규칙으로 정하는지까지만 다룬다. 그 값을 어디에 놓고 무슨 문구로 쓸지는 별도 세션에서 정한다. 아래는 그때 답해야 하는 것들이고, 각 항목이 기대는 엔진 쪽 규칙이 어디 있는지 함께 적는다.

- **완료 신호를 어디에 어떻게 보일지.** 켜지고 꺼지는 시점은 엔진이 정한다(위 "아직 안 정한 것" 참고)
- **관련 목록과 본문 위 상태의 문구.** 무엇이 어느 자리에 가는지는 2.3에서 정했다. "A가 B를 지지한다"처럼 관계 종류를 밝혀 쓰되, 실제 문장은 UX 라이팅 몫이다
- **주제 목록 행의 배치.** 뜨는 값과 셀 때 접힌 것을 빼는 규칙은 2.3에 있다
- **리뷰 화면.** 버튼은 어디서나 확정과 반려 둘이고, 충돌만 남길 쪽을 카드 안에서 고르며 기본 선택을 두지 않는다(2.5)
- **반려한 리뷰로 가는 입구.** 되돌리기가 유일한 복구 경로라(2.3) 입구가 안 보이면 없는 길이 된다. 며칠 지나 무엇을 반려했는지 기억 못 하는 상태에서도 닫힌 목록에서 찾아갈 수 있어야 한다
