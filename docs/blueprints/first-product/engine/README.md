## 07-modeling에서 달라지는 것

필드와 타입 정의는 그대로 `07-modeling.md`가 SSOT다. 다만 아래는 이번 라운드에 뒤집혀서 그쪽도 갱신해야 한다. 모르고 읽으면 이 문서와 정면으로 부딪힌다.

- **확정 게이트가 없다.** 정리가 끝나면 사람 확인 없이 저장된다
- **판정 단위가 진술이 아니라 다이제스트다**
- **대체와 병합은 관계 유형이 아니다.** 판정 기록에서 파생된다. 관계 유형은 중복·충돌·해소·지지·약화 다섯이고, 약화는 이번에 새로 생겼다
- **해소는 닫히는 쪽을 아카이브한다.** 그래서 사람이 판정한다
- **진술이 접혀도 관계는 연쇄로 안 접힌다.** 관계가 접히는 길은 그 관계를 만든 것을 되돌릴 때 하나뿐이다. 접힌 것을 감추는 목록도 없다. 접힌 표시를 달아 그대로 보여주고, 셀 때만 살아있는 것을 센다
- **진술은 다이제스트 유형별 주된 칸 하나씩만 나온다.** 다이제스트 하나에 진술 하나
- **한 다이제스트가 여러 곳과 동시에 중복이어도 판정은 하나만 올린다.** 그래서 07-modeling이 적어둔 무효화 시나리오(먼저 병합된 쪽이 나머지 중복 판정을 무효로 만든다)는 안 생긴다. `Changeset.invalidatedById` 자체는 남는다. 병합이 접힌 쪽에 걸려 있던 다른 유형의 대기 판정을 무효로 만드는 경로가 그 자리를 대신 쓴다

진술 필드도 바뀐다.

| 필드 | 어떻게 |
|---|---|
| `sourceField` | **`digestField`로 이름을 바꾼다.** 다이제스트의 칸이지 원문의 칸이 아니다 |
| `type` (claim/question) | 뺀다. 칸에서 나온다 |
| `confidence` | 뺀다. 이 설계 어디서도 안 본다 |
| `sourceFieldIndex` | 뺀다. 주된 칸 다섯이 다 단일 칸이라 셀 게 없다 |
| `referenceIds` | 뺀다. 인용 목록이 다이제스트 단위라 문장 단위로 이어둘 데가 없다 |

뒤의 넷은 나중에 되살릴 수 있다. `sourceFieldIndex`는 배열 칸을 다시 뽑을 때, `referenceIds`는 해설이 들어와 문장 단위 인용이 필요해질 때다.

## 아직 안 정한 것

- 화자를 "A"처럼 이름 없이 적은 경우 레퍼런스로 맞출지. 원문에 없는 걸 특정인으로 단정하면 틀렸을 때 엉뚱한 사람에게 발언이 붙는다
- 좁혀온 기존 레퍼런스가 하나도 없거나 여럿일 때 어떻게 고를지. 후보 유형과 기존 유형이 갈리는 경우("토스"를 조직으로 봤는데 기존은 제품)도 여기서 함께 정한다
- 레퍼런스 본문이 인용될 때마다 다시 쓰이며 자라는 걸 어떻게 누를지. 지금은 "사전이지 일지가 아니다"라는 기준뿐이고 상한은 없다
- 좁히기 상한을 무엇으로 얼마로 둘지. 개수인지 유사도 점수인지, 아니면 둘 다인지. 레퍼런스와 진술 양쪽 다. 진술 쪽은 중복·충돌과 지지·약화의 값이 갈린다
- 약화됨을 다이제스트 본문 위 상태로 올릴지. 지금은 관련 목록에만 뜬다. 본문 위 자리를 접힌 것 하나로 좁혀두려고 미뤘는데, 약화가 실제로 잘 잡히는 게 확인되면 그때 본다
- 제목을 원문에만 박을지, 변경셋에도 따로 박을지. 되돌린 뒤 다시 정리하면 제목이 새로 뽑히는데, 옛 변경셋이 그 시점의 이름을 지키려면 자기 제목이 있어야 한다
