# 표면 인벤토리: MVP 화면 목록

> nema MVP가 가질 화면(표면) 전체와 각 화면의 역할을 정리한다. 설계 방법론·판단 근거·리스크·자기검산은 `surface-design.md`가 맡고, 이 문서는 "지금 화면이 뭐고 무슨 역할인지"만 압축해서 담는다.

### 함께 보는 문서

- 표면 설계(`surface-design.md`): 이 인벤토리를 도출한 방법론과 굳힌 설계 원칙(판정 시 사람 주권, 아직 안 풀린 리스크, 나중으로 미룬 것 등).
- 용어 사전(`docs/guides/glossary.md`): 아래 등장하는 Source·Digest·Statement·Relation·Reference·Changeset·Topic·Tag·Thread·Workspace·Space·User·Member 정의.

---

## 로그인

User를 식별해 Workspace로 진입시킨다. Space가 없으면 기본 Space를 자동 생성해 Space 오버뷰로 보낸다.

## LNB

Workspace·User 표시 + Space 전환·생성 + 묻기·해설 + Reference 목록 진입점을 제공하는 전역 셸. (Tag는 별도 표면 없이 Digest 리뷰 화면의 셀렉트로 생성·수정됨)

## Space 오버뷰

**스레드 / 변경 이력**, 2개 탭으로 나뉘는 기본 착지 화면(스레드가 기본). 넣기 진입점을 함께 제공한다.

**탭 위 공유 영역** (탭과 무관하게 항상 표시):
- **처리 중인 Source 작업 목록** — Digest·Reference 생성 중인 Source가 여기 있다가, 완료되면 클릭해서 Digest 리뷰 화면으로 이동할 수 있다.
- **충돌 배너** — 새 충돌이 감지되면 뜨고, 액션을 누르면 스레드 탭의 "충돌만 보기" 필터가 자동으로 켜진다.

**스레드 탭**: Topic별 Digest 피드. 각 Digest 카드에는 Statement·Relation 생성 및 기존 Digest와의 충돌 판정 상태(진행 중→완료)가 GitHub CI 체크처럼 조용히 표시된다. "충돌만 보기" 필터 토글이 있다. 비어있으면 데모 라벨이 붙은 예시 데이터로 채워지고, 사용자가 지우거나 무시할 수 있다.

**변경 이력 탭**: [변경 이력](#변경-이력) 참고.

## Digest 상세 (사이드 패널)

목록(스레드 피드·묻기·해설 등)에서 Digest를 클릭하면 우측 사이드 패널로 뜬다 — 원래 화면의 흐름(스크롤 위치·대화 흐름)을 안 끊기 위함. 클릭한 Digest의 내용과, Statement 관계를 근거로 계산된 다른 Digest와의 관계를 보여준다. 근거가 된 Statement 관계는 펼쳐서 확인할 수 있다. 충돌이 있으면 판정을 통해 해소할 수 있다.

## Source 작성 (모달)

Space 오버뷰의 입력창을 클릭하면 모달로 확장돼 긴 글도 편하게 붙여넣을 수 있다.

## Digest 리뷰 화면

1개 Source에서 추출된 N개 Digest와 N개 Reference 후보를 확인하고 확정하는 전체 화면. 원본 Source를 나란히 두고 비교하며, 각 Digest는 제안된 Topic·Tag·타입과, 타입별 구조화된 본문을 보여준다. 이 시점엔 Statement가 아직 없어 충돌 판정은 여기서 하지 않는다. 이 화면에 보이는 내용은 1단계 완료 시 이미 "리뷰 대기" 상태로 생성된 Changeset이며, 확정하면 그 Changeset이 "확정" 상태로 바뀌면서 Statement·Relation 생성(2단계)이 시작되고, 그 Changeset 상세 화면으로 이동한다.

## 변경 이력

Space 오버뷰의 변경 이력 탭. 이 Space에서 일어난 모든 Changeset을 트리거(Source 제출·판정·수동 수정 등) 구분 없이 최신순으로 보여준다. 각 항목을 클릭하면 그 Changeset 상세 화면으로 이동한다. "Source 제출로 생긴 것만 보기" 필터로 좁혀볼 수 있다.

## Reference 목록

Workspace 전체에서 재사용되는 대상(사람·조직 등)·개념을 모아 보여주는 목록. 같은 이름이라도 서로 다른 대상이면 별개 엔트리로 존재하며, 각 Statement는 문맥에 따라 올바른 엔트리에 매핑된다. 엔트리를 클릭하면 Digest 상세와 같은 이유로 우측 사이드 패널이 열려, 그 Reference를 건드린 Changeset들(Source 제출로 생긴 것과 이 목록에서 직접 수정한 것 모두)을 이력으로 볼 수 있다.

(협업 확장 시 원칙: Reference 병합은 접근 권한이 일치하는 Space끼리만 허용하고, 권한이 다르면 중복을 허용한다 — 이력에 부분 가림이 생기는 걸 막기 위함)

## Changeset 상세 (사이드 패널)

변경 이력 탭에서 항목을 클릭하면 Digest 상세와 같은 이유로 우측 사이드 패널로 뜬다. 하나의 Changeset이 일으킨 변화(diff)만 보여준다 — 트리거가 Source 제출이면 그 원문과 새로 생긴 N개 Digest·Reference·Statement·Relation을, 판정이면 그 판정으로 바뀐 것만 보여준다. 나중에 다른 Changeset이 여기서 만든 걸 건드려도 그 변화는 그 Changeset 쪽에 표시되고 여기가 소급 갱신되진 않는다. 진행 중인 처리 상태가 조용히 표시되며, 사용자는 완료를 기다리지 않고 언제든 떠날 수 있다. 여기서 "되돌리기"를 실행하면 이 Changeset의 변화가 통째로 되돌려진다.

## Space 생성 (모달)

LNB에서 새 Space를 만들 때 이름을 입력하는 가벼운 모달. 생성하면 바로 그 Space로 전환된다. 아이콘·색상·삭제 같은 관리 기능은 필요성이 커지면 별도 설정 화면으로 확장을 고려한다.

## 계정 설정 (오버레이)

LNB의 User 표시를 클릭하면 뜨는 작은 드롭다운. User 기본 정보(이름·이메일)와 로그아웃, Workspace 이름을 보여준다. 별도 화면 없이 오버레이로 충분하다. 결제는 MVP에서 수동 처리라 인앱 UI를 두지 않는다.

## MCP 연결 관리

연결된 외부 에이전트(MCP 클라이언트) 목록을 보여주고 연결을 해제할 수 있는 화면. 새로 연결할 때는 OAuth 동의 화면에서 접근을 허용할지 확인한다.

## 묻기·해설

LNB에서 접근하는 전역 질문 화면. ChatGPT·Perplexity 같은 챗 인터페이스를 따라 입력창과 답변이 한 화면에서 대화형으로 이어진다. 질문을 던지면 Space를 가로질러 Statement·Relation·Digest·Reference를 검색하고, 그 결과를 Narration(산문 답)으로 보여준다.

일반 AI 챗봇과 다른 점: 답변의 모든 문장에 사용자 자신의 과거 Statement를 가리키는 근거 핸들이 달리고, 충돌이 있는 Digest는 클릭하면 Digest 상세 사이드 패널이 열려 대화 흐름을 유지한 채 그 자리에서 판정할 수 있으며, 근거가 없으면 지어내지 않고 명시적으로 모른다고 표시한다.
