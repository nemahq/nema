Memory 저장 흐름

"토스로 이직했다. 팀장이 김철수에서 이영희로 바뀌었다."

사용자가 저장 버튼을 누를 때 이 Draft가 아래 단계를 거쳐 Memory로 기록된다

0
저장 큐 등록 프론트엔드 non-blocking
저장 버튼을 누르면 즉시 큐에 등록되고 사용자는 바로 다음 작업을 시작할 수 있다. 실제 처리는 백그라운드에서 순차적으로 진행된다. Draft 본문은 save_jobs.draft_body에 보존되고, 세션의 편집 상태(session.draft)만 초기화된다.
save-job-service.ts
저장 버튼 클릭
Draft 본문 확정
→
save_jobs 생성
status: pending
→
Draft 초기화
session.draft = null
→
백그라운드 처리 시작
status: processing

저장이 여러 개 쌓여도 큐에서 순차 처리 → 앞선 저장 결과를 반영한 상태에서 다음 저장의 유사 검색이 수행되므로 충돌 없음. save_jobs.draft_body에 Draft 본문이 임시 보관되며, Step 4에서 histories.source_draft_body로 이관 후 null로 초기화된다.

1
토픽 분리
독립적인 주제가 섞여 있으면 나눈다. 애매하면 나누지 않는다. 이하 단계는 분리된 토픽별로 반복된다.
services/chat/saving.ts prompts/saving.ts · SPLIT_SYSTEM_PROMPT
토픽 A
토스로 이직했다.
토픽 B
팀장이 김철수에서 이영희로 바뀌었다.
2
관련 Memory 탐색 및 분류
벡터 검색으로 유사 Memory를 찾고, 각각에 대해 create / extend / replace를 판단한다. 토픽 하나가 여러 Memory에 걸치면 fan-out.
services/chat/saving.ts prompts/saving.ts · JUDGMENT_SYSTEM_PROMPT fan-out 미구현
토픽 A — 유사 Memory 1개 발견
replace커리어 이력
전스타트업 재직 중. 프로덕트 매니저.
후토스로 이직. 이전 직장(스타트업) PM 경험 보유.
토픽 B — 유사 Memory 3개 발견 → fan-out
replace팀 구성
전팀장: 김철수
후팀장: 이영희 (이전: 김철수)
replace김철수 프로필
전팀장 역할 수행 중.
후전 팀장. 현재 팀장 역할 종료.
extend이영희 프로필
전팀원. 시니어 엔지니어.
후팀원 → 팀장으로 선임. 시니어 엔지니어 출신.

Memory마다 replace / extend 독립 판단.

3
메타 생성
변경된 Memory별로 title / tags / summary를 생성한다. 한국어 콘텐츠는 영문 파생 필드(title_en 등)도 함께 생성.

title팀 구성 및 팀장 변경 이력

4
변경 사항 저장
이번 저장에서 발생한 모든 변경을 History 하나로 묶어 기록한다. save_jobs.draft_body는 histories.source_draft_body로 이관 후 null로 초기화된다.

replace김철수 프로필direct

직접 Revision 4개, 동일한 hist_abc123 참조 · 세션의 Draft 메시지에 history_id 업데이트 · ingestion_status = pending 설정 → 인제스천 트리거
5
검색 인덱스 갱신 백그라운드 · Phase 3
저장된 Memory를 임베딩·그래프로 변환해 검색 가능한 상태로 만든다.
미구현
임베딩 (Qdrant)
→4개 Memory 임베딩 생성 후 벡터 DB 저장
→이후 저장 시 유사 Memory 검색에 활용
엔티티 그래프 (Neo4j)
→엔티티 추출: 토스, 김철수, 이영희, 팀
→관계 기록: 이영희 → 팀장, 김철수 → 전 팀장
→다음 단계(간접 전파)에서 이 그래프 조회
6
간접 영향 전파 백그라운드 · Phase 4
이번에 바뀐 엔티티를 참조하는 다른 Memory들을 찾아 자동으로 재합성한다. 직접 수정하지 않았지만 맥락이 outdated된 Memory를 최신 상태로 유지.
미구현
변경된 엔티티 토스 이영희 김철수 → 이 엔티티를 참조하는 Memory 탐색
재합성 예정프로젝트 X 회고 — "토스" 관련 맥락 outdated. 재합성 큐 추가.
재합성 예정투자 메모 — 토스 언급 있음. 현재 상태 반영해 재합성.

→ 재합성 완료 후 Step 4의 History(hist_abc123)에 아래 Revision이 append됨:

replace프로젝트 X 회고propagated
extend투자 메모propagated

source: propagated으로 직접 수정과 구분. NEM-26(시간축 추적)·NEM-81(Lint)은 source = direct만 필터링.
