# UX Writing 가이드

## 톤앤매너

Nema는 B2C "되찾기 도구" — 사용자가 매일 편하게 생각을 맡기는 서비스.

| 언어 | 톤 | 키워드 |
|------|-----|--------|
| 한국어 | 해요체, 제안형, 친근함 | 토스 스타일 |
| 영어 | Professional yet friendly, sentence case | Linear 스타일 |

톤은 맥락에 따라 조절:
- **온보딩**: 격려, 가치 중심 (기능 용어 지양 — 첫 사용자는 모름)
- **에러**: 공감, 해결 안내 (사용자를 탓하지 않음)
- **설정**: 각 항목이 왜 필요한지 한 줄 설명

---

## 용어

`docs/guides/glossary.md`의 제품 용어를 사용자 노출 텍스트에 반드시 적용.

| 제품 기능 | 한국어 | 영어 |
|-----------|--------|------|
| Put-in 모드 | 기억하기 | Remember |
| Pull-out 모드 | 묻기 | Ask |
| 대화 공간 | 맥락 | Context |
| AI 중간 결과 | 초안 | Draft |
| AI 정리 작업 | 정리 | Organize |

- 한국어: 기능명을 문장에 쓸 때 "기억하기와 묻기에 사용하는 언어" 식으로 자연스럽게 녹임
- 영어: 기능명은 대문자로 고유명사 취급 — "Used when you Remember and Ask"

## 한국어 규칙

### 어조

| 규칙 | 예시 |
|------|------|
| 해요체 통일 | ✅ "로그인 링크를 보냈어요." / ❌ "로그인 링크를 보냈습니다." |
| 제안형 질문 | ✅ "맥락을 삭제할까요?" / ❌ "맥락을 삭제하시겠습니까?" |
| 사용자를 탓하지 않음 | ✅ "알 수 없는 오류가 발생했어요." / ❌ "잘못된 요청입니다." |

### 버튼/레이블

자연스러운 표현 우선. 무리한 통일보다 각 케이스에 맞게.

| 패턴 | 적합한 경우 | 예시 |
|------|------------|------|
| ~하기 | 행동이 명확한 동사구 | 보내기, 닫기, 시작하기, 돌아가기 |
| 명사 | 1~2음절 동사성 명사 | 저장, 취소, 삭제 |
| 명사구 | 짧은 복합 행동 | 다시 시도 |

### 마침표

| 유형 | 마침표 | 예시 |
|------|--------|------|
| 문장형 (주어+서술어) | 있음 | "삭제하면 되돌릴 수 없어요." |
| 레이블/명사구 | 없음 | "코드 복사" |
| 상태 표시 | 없음 | "저장 완료" |
| 진행 중 (...) | 없음 (말줄임표가 대신) | "저장 중..." |

### 띄어쓰기

| 규칙 | 예시 |
|------|------|
| "중"은 의존명사 → 띄어쓰기 | ✅ "작성 중" / ❌ "작성중" |

### 동의어 통일

한 개념에 한 단어만 사용.

| 통일 용어 | 사용하지 않는 표현 |
|-----------|-------------------|
| 중지 | 중단 |
| 맥락 | 세션 (사용자 노출 시) |

## 영어 규칙

### Sentence case

모든 UI 텍스트에 sentence case 적용 (첫 글자만 대문자).

| 예시 | 적용 |
|------|------|
| ✅ "New context" | ❌ "New Context" |
| ✅ "Shortcut guide" | ❌ "Shortcut Guide" |
| ✅ "Your contexts" | ❌ "Your Contexts" |

예외: 제품 기능명(Remember, Ask, Memory), 고유명사(Nema, Google).

### Voice

| 규칙 | 예시 |
|------|------|
| Active voice | ✅ "We saved your file." / ❌ "Your file was saved." |
| Plain language | ✅ "what you write" / ❌ "your input" |
| 2인칭 | ✅ "Used when you Remember and Ask" / ❌ "Language used for Remember and Ask" |

### 마침표

한국어와 동일 규칙 — 문장이면 마침표, 레이블이면 없음.

## 서버 에러 메시지

서버 i18n (`apps/server/src/infra/i18n/locales/`)에도 동일 톤 적용.

### 구조

모든 에러 메시지는 **원인 + 해결 안내** 구조:

| 언어 | 예시 |
|------|------|
| 한국어 | ✅ "요청이 너무 많아요. 잠시 후 다시 시도해주세요." / ❌ "Rate limit exceeded." |
| 영어 | ✅ "Too many requests. Please try again shortly." / ❌ "Rate limit exceeded." |

### 규칙

- 한국어: 해요체, 존댓말 유지
- 영어: Sentence case, 사용자 탓하지 않음
- 기술 용어 노출 금지 ("UNAUTHORIZED" → "로그인이 필요해요.")
