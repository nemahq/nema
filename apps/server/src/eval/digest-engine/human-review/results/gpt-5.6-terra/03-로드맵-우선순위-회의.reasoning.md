## [결정] 리드 업로드에 복사-붙여넣기 방식을 우선 채택

- **상황**: 리드 업로드 방식을 어떻게 구성할지 결정해야 했다.
- **선택**: CSV 업로드 대신 테이블 데이터를 복사-붙여넣기하는 방식을 우선 채택하고, 매핑과 기본 키 검증만 남긴다.
- **이유**: 기존 CSV 업로드는 유저·리드 분리, 필드 매핑, 옵션 설정 과정이 길고 무거워 실제로 잘 사용되지 않았으며, 테이블 형태 데이터는 붙여넣기만으로도 상당 부분 자동 인식할 수 있음을 확인했다.

> **판단 이유**: ‘CSV 업로드 대신 복사-붙여넣기 방식을 우선 채택하기로 했다’고 명시되어 있어 결정으로 분류했다.

## [결정] 이벤트 트리거에 룰베이스 선필터와 후속 LLM 적용

- **상황**: 대량 이벤트에 자연어 기반 LLM 필터링을 어떻게 적용할지 결정해야 했다.
- **선택**: 트리거를 룰베이스로 먼저 걸러 물량을 1% 수준(150만 건 이하)까지 줄인 뒤에만 LLM을 적용하며, 자연어 입력은 룰 생성의 보조 수단으로만 사용한다.
- **이유**: 월 이벤트가 1~2억 건 규모여서 모든 이벤트를 LLM에 처리하면 서버 비용을 감당할 수 없다는 점이 확인됐다.
- **대안**: 
  - 모든 이벤트를 자연어로 필터링하면 유연하게 처리할 수 있지만, 월 1~2억 건 전체를 LLM에 처리해야 해 서버 비용을 감당하기 어렵다.

> **판단 이유**: 룰베이스로 선별한 뒤에만 LLM을 적용하기로 ‘결정했다’고 명시되어 있어 결정이다.

## [결정] 이번 스프린트에서 콘텐츠 파트를 최우선 개발

- **상황**: 이번 스프린트에서 콘텐츠 파트와 시간 지정 자동 발송 기능 중 무엇을 우선 개발할지 정해야 했다.
- **선택**: B2B 리드젠에 필요한 콘텐츠 파트(캠페인 자료 구성)를 가장 먼저 개발하고, 정해진 시간에 자동 발송하는 기능은 나중으로 미룬다.
- **이유**: 콘텐츠 파트가 핵심이며, 시간 지정 기능은 천천히 만들어도 된다는 데 참석자들이 동의했다.
- **트레이드오프**: 
  - 정해진 시간에 자동으로 보내는 기능의 개발을 뒤로 미룬다.

> **판단 이유**: 개발 우선순위를 ‘가장 먼저 개발하기로 했다’고 명시하고 자동 발송 기능은 연기했으므로 별도의 결정으로 기록했다.

## [결정] 대시보드는 성과 요약만 제공

- **상황**: 대시보드에 상세 지표까지 포함할지 결정해야 했다.
- **선택**: 대시보드에는 캠페인 성과 요약만 보여주고, 세부 데이터는 별도 리포트 화면에서 확인하도록 한다.
- **이유**: 상세 지표까지 넣으면 화면이 복잡해진다는 우려가 있었다.
- **트레이드오프**: 
  - 대시보드에서 세부 데이터를 직접 확인할 수 없고 별도 리포트 화면으로 이동해야 한다.
- **대안**: 
  - 대시보드에 상세 지표까지 모두 넣으면 한 화면에서 세부 데이터를 확인할 수 있다.

> **판단 이유**: 대시보드와 별도 리포트의 정보 배치를 ‘정리했다’고 했으므로 결정으로 분류했다.

## [미결] 발신 채널 배치 위치 결정

- **질문**: 전화·문자 등 발신 채널을 오디언스 설정, 발송 기준, 별도 운영 화면 중 어디에 배치할 것인가?
- **배경**: 오디언스에 넣으면 연락처 입력을 자연스럽게 유도할 수 있지만, 오디언스 설정이 지나치게 무거워질 수 있다는 반론이 있다.
- **선택지**: 
  - 오디언스 설정에 넣기
  - 발송 기준 쪽에 넣기
  - 별도 운영 화면으로 분리하기
- **확인 조건**: 다음 회의에서 결론을 낸다.

> **판단 이유**: 세 가지 배치 방안 사이에서 의견이 갈렸고 ‘다음 회의로 넘겼다’고 명시되어 있어 미해결 사안이다.

## [미결] 캠페인 입력 스키마 생성 방식 결정

- **질문**: 캠페인 입력 스키마를 LLM이 자동 생성하게 할지, 정해진 함수 호출로 고정된 스키마를 사용할지?
- **배경**: LLM 자동 생성은 유연하지만 안정성이 아직 검증되지 않았다.
- **선택지**: 
  - LLM이 입력 스키마를 자동 생성하기
  - 정해진 함수 호출로 고정된 스키마 사용하기
- **확인 조건**: 성민과 도경이 이번 주 안에 어느 방식으로 갈지 결정한다.

> **판단 이유**: 두 방식 중 아직 정하지 않았고 담당자와 결정 시점이 명시되어 있어 보류 항목으로 분류했다.

## [학습] 테이블 데이터는 붙여넣기만으로 상당 부분 자동 인식 가능

- **발견**: 테이블 형태 데이터는 복사해 붙여넣기만 해도 상당 부분 자동 인식할 수 있다.

> **판단 이유**: ‘자동 인식이 가능하다는 걸 확인했다’고 명시된 확인 결과이므로 학습으로 기록했다.

## [학습] 전체 이벤트 LLM 처리의 서버 비용은 감당하기 어려움

- **발견**: 월 1~2억 건의 이벤트 전체를 LLM으로 처리하면 서버 비용을 감당하기 어렵다.
- **근거**: 월 이벤트 규모가 1~2억 건이다.

> **판단 이유**: 전체 LLM 처리 비용이 감당 불가하다는 점을 ‘이번에 확인됐다’고 서술했으므로 학습으로 분류했다.

## 제외된 판단 (3개)

- "기존 CSV 업로드는 실제로 잘 안 쓰이고 있었다." — 복사-붙여넣기 방식 채택 결정의 이유로 포함했으며, 별도의 독립 판단으로 분리하지 않았다.
- "콘텐츠 파트가 핵심이고 시간 지정은 천천히 만들어도 된다." — 스프린트 우선순위 결정의 이유와 비용으로 포함했으며, 독립된 판단으로 분리하지 않았다.
- "LLM 자동 생성은 유연하지만 안정성이 검증되지 않았다." — 캠페인 스키마 생성 방식에 관한 보류의 배경으로 포함했으며, 확정된 학습이나 독립 가정으로 분류하지 않았다.
