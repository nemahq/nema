# 08-AI-세션-대화-로그 (reasoning)

## [결정] 캐시 무효화에 30초 TTL을 우선 적용

- **상황**: 캐시 무효화를 TTL 방식으로 할지 이벤트 기반으로 할지 결정해야 했다.
- **선택**: 캐시 무효화 전략으로 우선 TTL 30초를 적용하고, 이벤트 기반 무효화는 여유가 생기면 나중에 추가한다.
- **이유**: 트래픽 패턴상 이벤트 기반 방식이 맞을 수 있지만, 현재 리소스로는 구현 복잡도를 감당하기 부담스럽기 때문이다.
- **트레이드오프**: 
  - 최대 30초 동안 오래된 데이터를 보여줄 수 있다.
- **대안**: 
  - 데이터 변경 시점에 캐시를 지우는 이벤트 기반 무효화를 지금 도입한다.

> **판단 이유**: 정우가 절충안으로 제시된 짧은 TTL 방식을 두고 “일단 그렇게 가자. TTL 30초로 시작”이라고 명시적으로 채택했다. 이벤트 기반 방식은 현재 도입하지 않고 추후 추가하는 대안으로 남겼다.

## [미결] 캐시 키에 사용자 ID를 미리 포함할지 여부

- **질문**: 향후 사용자별 데이터 제공 기능을 대비해 지금 캐시 키에 사용자 ID를 포함할지 결정해야 한다.
- **배경**: 현재 캐시 키는 리소스 ID만으로 구성되어 있으며, 사용자별 데이터 기능은 아직 확정되지 않았다.
- **선택지**: 
  - 지금 캐시 키에 사용자 ID를 포함한다.
  - 사용자별 데이터 기능이 필요하다고 판단되는 시점에 사용자 ID 포함을 다시 논의한다.

> **판단 이유**: 사용자 ID를 미리 넣자는 제안에 대해 정우가 “좀 더 생각해볼게”라고 하며 결정을 유보했다. 기능 확정 여부와 불필요한 복잡도 증가 우려가 열린 판단 기준으로 제시되었다.

## 제외된 판단 (1개)

- "마지막에 ‘일단 TTL 30초짜리부터 붙여볼게’라고 다시 언급함" — 앞서 확정된 30초 TTL 적용 결정의 재확인 및 실행 계획으로, 별도의 판단이 아니다.
