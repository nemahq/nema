# 08-AI-세션-대화-로그 (reasoning)

digest count: 5

## [결정] 캐시는 우선 30초 TTL로 운영

- **상황**: 이벤트 기반 무효화와 TTL 방식 중 현재 적용할 캐시 무효화 전략을 정해야 했다.
- **선택**: 캐시 무효화는 우선 TTL 30초 방식으로 시작하고, 이벤트 기반 무효화는 나중에 여유가 생기면 추가한다.
- **이유**: 트래픽 패턴상 이벤트 기반이 더 맞을 수 있지만, 현재 리소스로는 구현 복잡도를 감당하기 부담스럽다.
- **트레이드오프**: 
  - 최대 30초 동안 오래된 데이터를 보여줄 수 있다.
- **대안**: 
  - 이벤트 기반 무효화는 데이터 변경 시 즉시 무효화해 항상 최신 데이터를 제공할 수 있다.

> **판단 이유**: 정우가 절충안을 수용하며 “일단 그렇게 가자. TTL 30초로 시작”이라고 확정했고, 마지막에도 이를 다시 실행하겠다고 했다.

## [미결] 캐시 키에 사용자 ID를 지금 포함할지 검토

- **질문**: 향후 사용자별 데이터 제공 기능을 대비해 캐시 키에 사용자 ID를 지금부터 포함할지 결정해야 한다.
- **배경**: 현재 캐시 키는 리소스 ID만 사용한다. 사용자별 기능은 아직 확정되지 않았다.
- **선택지**: 
  - 지금 캐시 키에 사용자 ID를 포함한다.
  - 사용자별 기능이 필요하다고 판단될 때 사용자 ID를 포함한다.
- **확인 조건**: 사용자별 데이터 제공 기능의 필요성 또는 도입 여부가 확정되면 결정한다.

> **판단 이유**: 정우가 이 제안에 대해 “좀 더 생각해볼게”라고 하며 결론을 유보했다.

## [가정] 이벤트 기반 무효화가 현재 트래픽 패턴에 더 적합할 수 있음

- **가설**: 현재 트래픽 패턴에는 이벤트 기반 무효화가 더 맞을 것 같다.
- **영향**: 이 가정이 맞더라도 현재는 구현 복잡도 때문에 TTL 방식으로 먼저 시작한다.

> **판단 이유**: 정우가 “이벤트 기반이 맞을 것 같긴”이라고 헤지된 판단을 제시했다. 검증된 사실이 아니라 전략 적합성에 관한 추정이다.

## [가정] 사용자 ID를 미리 캐시 키에 넣으면 향후 마이그레이션 비용이 낮을 수 있음

- **가설**: 사용자별 기능을 대비해 지금 캐시 키에 사용자 ID를 포함하면 나중에 마이그레이션하는 것보다 비용이 적게 들 수 있다.

> **판단 이유**: AI가 “훨씬 쌀 것 같은데”라고 추정형으로 제시한, 향후 구현 비용에 관한 검증되지 않은 판단이다.

## [가정] 사용하지 않을 사용자 ID 키는 불필요한 복잡도를 늘릴 수 있음

- **가설**: 사용자별 기능을 실제로 쓰지 않게 되면, 캐시 키에 사용자 ID를 미리 넣는 것은 불필요한 복잡도만 늘릴 수 있다.
- **근거**: 사용자별 데이터 제공 기능은 아직 확정되지 않았다.
- **검증 조건**: 사용자별 기능의 도입 여부가 확정되면 확인할 수 있다.

> **판단 이유**: 정우가 미리 키를 추가하는 선택의 결과를 “복잡도만 늘리는 걸 수도” 있다고 조건부로 추정했다.

## 제외된 판단 (3개)

- "TTL은 구현이 간단하지만 만료 전까지 오래된 데이터를 보여줄 수 있다." — 채택된 TTL 결정의 이유와 실제 감수한 비용으로 각각 반영되어 별도 판단으로 분리하지 않았다.
- "이벤트 기반 무효화는 최신성을 보장하지만 구현이 복잡하고, 이벤트 누락 시 버그가 날 수 있다." — 채택하지 않은 이벤트 기반 대안의 장점 및 선택을 막은 구현 복잡도 맥락으로 결정 항목에 반영했다. 이벤트 누락 위험은 최종 선택의 독립적인 결론으로 제시되지 않았다.
- "TTL을 짧게 잡고 이벤트 기반 무효화는 나중에 추가하자는 절충안." — 정우가 수용해 최종 결정으로 기록했다.
