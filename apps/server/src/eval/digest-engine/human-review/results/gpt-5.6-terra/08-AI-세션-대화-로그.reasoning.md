# 08-AI-세션-대화-로그 (reasoning)

## [결정] 캐시 무효화는 30초 TTL로 시작

- **상황**: 캐시 무효화 전략으로 TTL 방식과 이벤트 기반 무효화 방식 중 어떤 방향으로 갈지 결정해야 했다.
- **선택**: 캐시 무효화 전략으로 TTL을 30초로 설정해 우선 적용하고, 이벤트 기반 무효화는 나중에 추가한다.
- **이유**: 이벤트 기반 방식이 현재 트래픽 패턴에는 맞을 수 있지만, 현재 리소스로는 구현 복잡도를 감당하기 부담스럽다.
- **트레이드오프**: 
  - TTL이 만료되기 전까지는 오래된 데이터를 최대 30초간 보여줄 수 있다.
- **대안**: 
  - 이벤트 기반 무효화를 지금 적용 — 현재 리소스로 구현 복잡도를 감당하기 부담스럽다.

> **판단 이유**: 정우가 절충안에 동의하며 “TTL 30초로 시작”하겠다고 명시했으므로, 무효화 전략에 관한 확정된 결정이다. 이벤트 기반 방식은 검토됐으나 복잡도 부담 때문에 지금 적용하지 않는 경로로 남았다.

## [미결] 캐시 키에 사용자 ID를 지금 포함할지 검토

- **질문**: 향후 사용자별로 다른 데이터를 제공할 가능성에 대비해, 캐시 키에 사용자 ID를 지금부터 포함할지 결정해야 한다.
- **배경**: 현재 캐시 키는 리소스 ID만 사용한다. 향후 사용자별 데이터 기능이 추가되면 사용자 ID를 포함해야 할 수 있다.
- **선택지**: 
  - 지금 캐시 키에 사용자 ID를 포함 — 나중에 마이그레이션하는 것보다 비용이 적을 수 있다.
  - 기능 필요성이 확정된 뒤에 사용자 ID를 포함 — 현재 기능이 확정되지 않았고, 미리 넣었다가 사용하지 않으면 복잡도만 늘어날 수 있다.
- **확인 조건**: 사용자별로 다른 데이터를 보여주는 기능이 필요하다고 판단되거나 확정되면 다시 결정한다.

> **판단 이유**: 정우가 사용자 ID 포함 여부에 대해 “좀 더 생각해볼게”라고 하여 결론을 내리지 않았다. 지금 추가하는 방안과 필요 시 추가하는 방안의 근거가 모두 제시되어 있어 미결정 사안으로 기록한다.

## 제외된 판단 (2개)

- "“우리 트래픽 패턴 보면 이벤트 기반이 맞을 것 같긴 하다.”" — 이벤트 기반 무효화가 더 적합할 수 있다는 평가는 TTL 우선 적용 결정의 상황과 이유에 포함했다.
- "“TTL 30초짜리부터 붙여볼게.”" — 앞서 확정된 TTL 30초 적용 결정을 반복해 확인한 발언이므로 별도 판단으로 만들지 않았다.
