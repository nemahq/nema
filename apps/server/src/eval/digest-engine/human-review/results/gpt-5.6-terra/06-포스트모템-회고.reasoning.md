# 06-포스트모템-회고 (reasoning)

digest count: 9

## [결정] LLM 응답 검증에 반복 실행을 필수로 함

- **상황**: PPA 테스트를 한 번 통과한 뒤에도 동일 프롬프트의 결과가 반복 실행마다 달랐다.
- **선택**: LLM 응답의 랜덤성을 확인하기 위해 최소 반복 실행을 수행하는 것을 규칙으로 정했다.
- **이유**: 같은 프롬프트를 다섯 번, 열 번 반복했을 때 결과가 매번 달랐기 때문이다.

> **판단 이유**: 한 번의 통과만으로 검증을 끝내지 않기로 하는 운영 규칙을 명시적으로 세웠으므로 결정으로 분류했다.

## [결정] 수동 시스템 프롬프트 검토 방식을 버림

- **상황**: 프롬프트 문제를 찾아 수정하는 테스트·개선 방식이 필요했다.
- **선택**: 시스템 프롬프트를 한 줄씩 손으로 읽어 문제를 찾고 고치는 기존 방식을 사용하지 않기로 했다.
- **이유**: 기존 방식은 너무 번거로웠다.
- **대안**: 
  - 리플레이 기능으로 실패 대화 히스토리를 재생하며 검증하는 방식

> **판단 이유**: 기존 방식을 '너무 번거로웠다'고 평가하고 리플레이 방식으로 전환한 맥락에서, 기존 후보를 명시적으로 배제한 결정으로 포함했다.

## [결정] 리플레이 기반 검증 방식으로 전환

- **상황**: 프롬프트의 문제를 찾아 수정하는 과정을 더 수월하게 해야 했다.
- **선택**: 실패한 대화 히스토리를 그대로 재생하는 리플레이 기능을 사용해 검증한다.
- **이유**: 리플레이 기능으로 전환한 뒤 해당 과정이 크게 줄었다.
- **대안**: 
  - 시스템 프롬프트를 한 줄씩 손으로 읽으며 문제점을 찾아 고치는 방식 — 너무 번거로웠다.

> **판단 이유**: 기존 수동 검토 방식에서 리플레이 기능으로 전환한 것은 테스트 방법에 관한 선택이며, 전환 뒤 과정이 줄었다는 이유가 함께 제시됐다.

## [결정] 단순·복잡 동작별 성공률 기준 설정

- **상황**: 대화 삭제 처리처럼 단순해 보이는 동작도 edge case 테스트에서 60~80% 성공률에 그쳤다.
- **선택**: 단순한 동작은 100% 통과를 목표로 하고, 복잡한 동작은 10회 중 1회 실패까지 허용한다.

> **판단 이유**: 성공률 허용 기준을 구체적으로 확정했다고 명시되어 있어 결정으로 분류했다.

## [결정] 배포 전 전체 회귀 테스트 통과를 의무화

- **상황**: 이번 이슈 이전에는 회귀 테스트 통과 확인 단계가 느슨했다.
- **선택**: 프롬프트를 수정한 뒤 기존 회귀 테스트를 모두 통과해야만 배포한다.

> **판단 이유**: 배포 조건을 새로 확정한 명시적 운영 결정이다.

## [미결] 에이전트 역할 분리 여부

- **질문**: 서브 에이전트와 루트 에이전트로 역할을 나눌지, 하나의 에이전트가 계속 모든 처리를 맡을지 결정해야 한다.
- **배경**: 루트 에이전트가 서브 에이전트의 지식을 모두 알아야 역할 분리가 의미가 있지만, 현재 구조에서는 이를 충족하지 못한다.
- **선택지**: 
  - 서브 에이전트와 루트 에이전트로 역할 분리 — 루트 에이전트가 서브 에이전트의 지식을 전부 알아야 의미가 있는데 현재 구조로는 그렇게 할 수 없다.
  - 하나의 에이전트가 모든 처리 담당
- **확인 조건**: 다음에 시간을 따로 잡아 다시 검토한다.

> **판단 이유**: 두 가지 구조 사이에서 결론을 내리지 못했고, 추후 재논의하기로 했으므로 미해결 의사결정으로 분류했다.

## [학습] 단순한 동작도 낮은 성공률을 보일 수 있음

- **발견**: 로직상 단순해 보이는 동작이라도 프롬프트만으로는 성공률이 낮게 나올 수 있으며, 복잡도와 성공률은 항상 비례하지 않는다.
- **근거**: 상담 봇의 대화 삭제 처리에서 '삭제 호출 여부 판단'은 단순한 동작이었지만 edge case 테스트 성공률이 60~80%였다.

> **판단 이유**: 테스트 결과를 통해 복잡도와 성공률의 관계에 대해 확인한 사실로 서술되어 있어 학습으로 분류했다.

## [학습] 한 번의 PPA 테스트 통과는 안정성을 보장하지 않음

- **발견**: 한 번의 PPA 테스트 통과만으로는 충분하지 않으며, 같은 프롬프트를 반복 실행하면 결과가 달라질 수 있다.
- **근거**: 같은 프롬프트를 다섯 번, 열 번 반복 실행했을 때 결과가 매번 달랐다.

> **판단 이유**: 반복 실행에서 결과 변동을 관찰해 LLM 응답의 랜덤성을 확인한 사실이므로 학습으로 분류했다.

## [학습] 자동 개선 제안에는 사람 검토가 필요함

- **발견**: 자동화 도구의 프롬프트 수정 제안은 참고하되, 적용 전에 사람이 반드시 검토해야 한다.
- **근거**: 자동 개선 제안을 그대로 적용했을 때 다른 케이스가 깨진 경우가 있었다.

> **판단 이유**: 자동 제안을 그대로 적용한 결과 발생한 문제를 근거로 검토 필요성을 다시 확인했으므로 학습으로 분류했다.
