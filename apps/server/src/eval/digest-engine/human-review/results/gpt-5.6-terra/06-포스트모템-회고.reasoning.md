# 06-포스트모템-회고 (reasoning)

digest count: 8

## [결정] 프롬프트 수정 후 전체 회귀 테스트 통과를 배포 조건으로 설정

- **상황**: 이번 이슈 이전에는 프롬프트 수정 후 회귀 테스트 단계가 느슨했다.
- **선택**: 프롬프트를 수정한 뒤 기존 회귀 테스트를 모두 통과해야만 배포한다.

> **판단 이유**: 배포를 위한 명시적 기준을 확정했으므로 결정이다. 기존 회귀 테스트를 모두 통과시키는 조건이 선택 내용으로 직접 제시되었다.

## [결정] 단순·복잡 동작별 성공률 기준 설정

- **상황**: 대화 삭제 처리처럼 단순해 보이는 동작의 edge case 성공률이 60~80%로 나타났다.
- **선택**: 단순한 동작은 100% 통과를 목표로 하고, 복잡한 동작은 10번 중 1번 실패까지 허용한다.

> **판단 이유**: 성공률을 어느 수준까지 허용할지에 대해 구체적인 기준을 확정했으므로 결정이다.

## [결정] LLM 응답 검증에 반복 실행 적용

- **상황**: 같은 프롬프트를 다섯 번, 열 번 반복 실행했을 때 결과가 매번 달랐다.
- **선택**: LLM 응답의 랜덤성을 확인하기 위해 최소한의 반복 실행을 규칙으로 둔다.
- **이유**: 한 번의 PPA 테스트 통과만으로는 응답의 안정성을 확인할 수 없기 때문이다.

> **판단 이유**: ‘최소 반복 실행이 필요하다’를 규칙으로 세웠다고 명시했으므로, 테스트 방식에 관한 결정으로 분류했다.

## [결정] 자동 프롬프트 개선안은 사람 검토 후 적용

- **상황**: 자동화 도구의 제안대로 수정안을 적용했을 때 다른 케이스가 깨진 사례가 있었다.
- **선택**: 자동화 도구의 프롬프트 수정 제안은 참고만 하고, 적용 전에 사람이 반드시 검토한다.
- **이유**: 자동 제안을 그대로 적용하면 다른 케이스를 손상시킬 수 있기 때문이다.
- **대안**: 
  - 자동화 도구가 출력한 프롬프트 수정안을 그대로 적용한다.

> **판단 이유**: 자동 개선안을 다루는 절차로 사람 검토 단계를 반드시 두기로 했으므로 결정이다. 자동 적용은 실제로 시도되었으나 문제를 일으킨 대안으로 제시되었다.

## [결정] 문제 분석 방식을 히스토리 리플레이로 전환

- **상황**: 시스템 프롬프트를 한 줄씩 읽으며 문제를 찾아 고치는 기존 방식은 번거로웠다.
- **선택**: 시스템 프롬프트를 한 줄씩 수동으로 검토하는 대신, 실패한 대화 히스토리를 재생하는 리플레이 방식으로 전환했다.
- **이유**: 리플레이 기능으로 전환한 뒤 문제 분석 과정이 크게 줄었기 때문이다.
- **대안**: 
  - 시스템 프롬프트를 한 줄씩 수동으로 읽으며 문제점을 찾아 수정한다.

> **판단 이유**: 기존 수동 검토 방식에서 리플레이 방식으로 이미 전환한 선택이 서술되어 있어 결정으로 기록했다.

## [미결] 서브 에이전트와 루트 에이전트의 역할 분리 여부

- **질문**: 서브 에이전트와 루트 에이전트로 역할을 나눌지, 현재처럼 하나의 에이전트가 모든 처리를 맡게 둘지 결정해야 한다.
- **배경**: 역할 분리가 의미 있으려면 루트 에이전트가 서브 에이전트의 지식을 모두 알고 있어야 하지만, 현재 구조는 이를 지원하지 않는다.
- **선택지**: 
  - 서브 에이전트와 루트 에이전트로 역할을 분리한다.
  - 하나의 에이전트가 모든 처리를 맡도록 유지한다.
- **확인 조건**: 추후 시간을 따로 잡아 다시 검토한다.

> **판단 이유**: 두 운영 구조 사이의 선택이 명시적으로 결론 나지 않았으므로 미결정 사안이다.

## [학습] 단순한 동작도 낮은 성공률을 보일 수 있음

- **발견**: 동작의 논리적 복잡도와 성공률은 항상 비례하지 않으며, 단순해 보이는 동작도 낮은 성공률을 보일 수 있다.
- **근거**: ‘삭제 호출 여부 판단’처럼 단순한 로직의 프롬프트 테스트가 edge case에서 60~80% 성공률에 그쳤다.

> **판단 이유**: 이번 테스트 결과를 통해 확인한 사실로 서술되어 있으며, 성공률 수치가 이를 뒷받침한다.

## [학습] 동일 프롬프트의 반복 실행 결과는 달라질 수 있음

- **발견**: 같은 프롬프트라도 반복 실행하면 결과가 매번 달라질 수 있다.
- **근거**: 동일 프롬프트를 다섯 번, 열 번 반복 실행했을 때 결과가 매번 달랐다.

> **판단 이유**: 반복 실행에서 관측된 응답 변동성을 확인한 내용이므로 학습이다.

## 제외된 판단 (3개)

- "대화 삭제 처리 기능의 edge case 테스트 성공률이 60%, 80%로 나와 예상보다 낮았다." — ‘단순한 동작도 낮은 성공률을 보일 수 있음’ 학습의 근거로 포함했다.
- "리플레이 기능으로 더 일찍 바꿨어야 했다는 의견이 나왔다." — 리플레이 방식으로 전환한 결정에 대한 회고성 평가이며, 별도의 판단으로 분리하지 않았다.
- "다음에 시간을 잡고 역할 분리 문제를 다시 보기로 했다." — 미결정 사안을 재검토하기 위한 후속 작업 일정으로, 역할 분리 여부라는 pending에 이미 맥락으로 반영했다.
