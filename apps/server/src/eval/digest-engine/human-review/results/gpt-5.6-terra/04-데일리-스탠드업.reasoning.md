# 04-데일리-스탠드업 (reasoning)

digest count: 5

## [결정] 결제 API 테스트를 샌드박스 계정으로 계속 진행

- **상황**: 결제 API 연동 중 PG사 응답이 계속 비정상적으로 왔고, 실제 계정 심사 결과는 아직 나오지 않았다.
- **선택**: 실제 계정 심사가 나올 때까지 결제 API 테스트는 샌드박스 계정으로 계속 진행하기로 했다.
- **이유**: 실제 계정은 다음 주에나 나올 것으로 보인다.

> **판단 이유**: PG사 응답 문제와 실제 계정 심사 대기 상황에서 테스트 계정을 어떻게 운영할지에 대해 '샌드박스로 계속 테스트하기로 함'이라고 명시적으로 결정했다.

## [결정] CI 속도 개선을 백로그에 유지

- **선택**: CI 속도 개선 작업은 계속 백로그에 두기로 했다.

> **판단 이유**: CI 속도 개선을 즉시 진행하지 않고 계속 백로그에 유지한다는 작업 우선순위 판단이 기록되어 있다.

## [미결] 디자인 시스템 후속 작업의 우선순위 조정

- **질문**: 디자인 시스템 컴포넌트 3개를 마무리한 뒤 다음 작업의 우선순위를 어떻게 정할지 아직 결정되지 않았다.
- **배경**: 라희가 디자인 시스템 컴포넌트 3개를 마무리했다.
- **확인 조건**: 오늘 오후 지훈과 별도로 논의하기로 했다.

> **판단 이유**: 후속 작업 우선순위를 다시 맞춰야 한다고 했지만 결론은 내리지 않았고, 별도 논의로 결정하기로 했다.

## [학습] 온보딩 퍼널 3단계의 이탈이 특히 높음

- **발견**: 온보딩 퍼널 데이터에서 3단계의 이탈이 유독 많다.
- **근거**: 온보딩 퍼널 데이터를 확인한 결과다.

> **판단 이유**: 데이터를 확인해 특정 단계의 이탈이 많다는 사실을 관찰 결과로 보고했으므로 학습으로 분류했다.

## [가정] 온보딩 3단계 이탈 원인은 UX 문제일 수 있음

- **가설**: 온보딩 퍼널 3단계의 높은 이탈은 UX 문제일 것이라고 보고 있다.
- **검증 조건**: 정확한 원인을 확인하면 검증될 수 있다.

> **판단 이유**: 원인은 아직 정확히 모르지만 UX 문제일 것이라고 추정하고 있으므로, 확인되지 않은 상태에 관한 가정으로 분류했다.

## 제외된 판단 (5개)

- "“어제 배포한 검색 로직 이상 없음. 오늘은 이미지 OCR 쪽 마저 붙일 예정.”" — 검색 로직 상태 보고와 이미지 OCR 작업 계획으로, 이후에 왜 그렇게 했는지 재검토할 판단을 담고 있지 않은 업무 업데이트다.
- "“테스트 커버리지 늘리는 중, 특이사항 없음.”" — 진행 중인 작업의 상태 보고일 뿐 판단이나 미해결 선택지를 제시하지 않는다.
- "“PG사 응답이 계속 이상하게 와서” 및 “실제 계정은 다음 주에나 나올 것 같음.”" — 샌드박스 계정으로 계속 테스트하기로 한 결정의 상황과 이유에 이미 포함되어 있어 별도 digest로 만들지 않았다.
- "“정확한 원인은 아직 모르겠고”" — 온보딩 이탈 원인이 UX 문제라는 가정의 미확정 상태 및 검증 조건에 포함되어 있어 별도 pending으로 만들지 않았다.
- "“인프라 쪽 특이사항 없음.”" — 특이사항이 없다는 단순 상태 보고로, 기록할 판단이 없다.
