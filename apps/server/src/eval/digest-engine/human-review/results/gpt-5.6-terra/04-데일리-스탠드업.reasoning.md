# 04-데일리-스탠드업 (reasoning)

digest count: 7

## [결정] PG 실계정 심사 전까지 샌드박스 계정으로 테스트 지속

- **상황**: 결제 API 연동 중 PG사 응답이 계속 비정상적으로 왔다.
- **선택**: 실제 계정 심사 결과가 나올 때까지 샌드박스 계정으로 계속 테스트한다.
- **이유**: PG사 응답이 계속 이상하게 왔기 때문이다.
- **대안**: 
  - 실제 계정으로 테스트를 진행하는 방안

> **판단 이유**: PG사 응답 문제에 대응해 테스트 환경을 샌드박스로 유지하기로 명시적으로 정한 결정이다. 실제 계정 사용은 심사 결과가 나올 때까지 진행하지 않는 경로로 제시됐다.

## [결정] CI 속도 개선은 백로그에 유지

- **선택**: CI 속도 개선 작업을 계속 백로그에 둔다.

> **판단 이유**: CI 속도 개선이 현재 착수하지 않고 계속 백로그에 있다고 서술되어 있어, 해당 작업의 우선순위를 미루는 지속적인 결정으로 포함했다.

## [미결] 디자인 시스템 후속 작업의 우선순위 재조정

- **질문**: 디자인 시스템 컴포넌트 3개를 마무리한 뒤 다음 작업의 우선순위를 어떻게 다시 정할 것인가?
- **배경**: 라희가 디자인 시스템 컴포넌트 3개를 마무리했다.
- **확인 조건**: 오늘 오후 지훈과 별도로 논의한다.

> **판단 이유**: 다음 작업의 우선순위를 다시 맞춰야 한다고 했지만 어떤 우선순위로 정할지는 아직 결론나지 않았다. 오후 논의가 예정되어 있어 미결 질문으로 분류했다.

## [학습] 배포된 검색 로직에 이상 없음

- **발견**: 어제 배포한 검색 로직에는 이상이 없다.

> **판단 이유**: 도현이 전날 배포한 검색 로직에 이상이 없다고 확인했다. 이를 뒷받침하는 별도의 관측이나 수치는 노트에 없다.

## [학습] 온보딩 퍼널 3단계의 이탈이 특히 많음

- **발견**: 온보딩 퍼널에서 3단계 이탈이 유독 많다.
- **근거**: 온보딩 퍼널 데이터를 확인한 결과다.

> **판단 이유**: 지훈이 퍼널 데이터를 보고 3단계 이탈이 많다는 사실을 확인했다고 보고했다. 데이터 확인이 이 발견의 근거로 제시됐다.

## [가정] PG 실계정 심사 결과는 다음 주에 나올 가능성

- **가설**: PG 실제 계정 심사 결과는 다음 주에나 나올 것 같다.
- **영향**: 그때까지 샌드박스 계정으로 테스트를 계속한다.
- **검증 조건**: PG 실제 계정 심사 결과가 나온다.

> **판단 이유**: 실계정 심사 시점은 '것 같음'으로 표현된 미확인 예측이다. 이 예측은 샌드박스 테스트를 유지하는 결정의 전제가 된다.

## [가정] 온보딩 3단계 이탈 원인은 UX 문제일 가능성

- **가설**: 온보딩 3단계의 높은 이탈은 UX 문제일 것이다.
- **근거**: 3단계에서 이탈이 유독 많다는 퍼널 데이터가 관찰됐다.
- **검증 조건**: 이탈 원인에 대한 정확한 분석이 이뤄진다.

> **판단 이유**: 정확한 원인은 아직 모른다고 한 뒤 UX 문제라고 보고 있으므로, 확인되지 않은 원인 가설이다. 3단계 이탈 데이터는 이 가설을 세운 배경으로만 제시됐다.

## 제외된 판단 (4개)

- "도현이 오늘 이미지 OCR 연동을 마저 진행할 예정" — 단순 작업 계획으로, 완료 후에도 왜 그렇게 했는지를 다시 물을 판단이 아니다.
- "세아가 테스트 커버리지를 늘리는 중이며 특이사항 없음" — 진행 상황 보고와 이상 없음이라는 상태 보고로, 별도의 판단을 담고 있지 않다.
- "라희가 디자인 시스템 컴포넌트 3개를 마무리함" — 완료된 작업의 상태 보고이며, 후속 작업 우선순위에 관한 미결 판단은 별도 pending으로 기록했다.
- "인프라 쪽 특이사항 없음" — 단순 상태 보고로, 별도의 확인 가능한 발견이나 선택지가 제시되지 않았다.
