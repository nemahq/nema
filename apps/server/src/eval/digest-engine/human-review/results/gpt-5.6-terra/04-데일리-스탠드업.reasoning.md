# 04-데일리-스탠드업 (reasoning)

digest count: 8

## 원문 제목

4월 9일 데일리 스탠드업: 개발 진행 현황과 결제·온보딩 이슈

> **판단 이유**: 검색·OCR·테스트·디자인 시스템·인프라의 진행 상황과 함께 결제 테스트 환경, 작업 우선순위, 온보딩 이탈 문제를 다룬 전체 스탠드업 내용에 기반한 제목이다. 특정 한 판단이 아니라 노트 전반의 주제를 포괄한다.

## [결정] 실계정 심사 전까지 샌드박스 계정으로 결제 API 테스트 지속

- **상황**: 결제 API 연동 중 PG사 응답이 계속 비정상적으로 왔고, 실제 계정은 아직 심사 중이다.
- **선택**: 실제 계정 심사 결과가 나올 때까지 샌드박스 계정으로 결제 API 테스트를 계속하기로 했다.
- **이유**: 실제 계정은 다음 주에나 나올 것으로 보인다.

> **판단 이유**: PG사 응답 문제와 실제 계정 부재라는 상황에서 테스트 계정을 어떻게 운영할지 명시적으로 정한 내용이므로 결정이다.

## [결정] CI 속도 개선을 백로그에 유지

- **선택**: CI 속도 개선은 계속 백로그에 두기로 했다.

> **판단 이유**: CI 개선의 현재 우선순위를 백로그로 유지한다는 지속적인 우선순위 판단이 언급되어 있어 결정으로 분류했다.

## [미결] 디자인 시스템 후속 작업 우선순위 재조정

- **질문**: 디자인 시스템 컴포넌트 3개를 마무리한 뒤 다음 작업의 우선순위를 어떻게 정할지 결정해야 한다.
- **배경**: 디자인 시스템 컴포넌트 3개를 마무리했다.
- **확인 조건**: 오늘 오후 지훈과 별도로 논의하기로 했다.

> **판단 이유**: 후속 작업 우선순위를 다시 맞출 필요가 있다고 했지만 아직 방향을 정하지 않았으므로 미결 사항이다.

## [학습] 배포된 검색 로직에서 이상 없음

- **발견**: 어제 배포한 검색 로직에는 이상이 없다.

> **판단 이유**: 검색 로직의 배포 후 상태를 이상 없다고 확인한 내용이므로 학습으로 기록했다.

## [학습] PG사 응답 이상 지속

- **발견**: 결제 API 연동 중 PG사 응답이 계속 비정상적으로 오고 있다.

> **판단 이유**: 결제 API 연동 과정에서 반복적으로 관찰된 문제 상태를 보고한 내용이다. 이는 샌드박스 테스트 지속 결정의 근거이기도 하다.

## [학습] 온보딩 3단계 이탈 집중

- **발견**: 온보딩 퍼널에서 3단계의 이탈이 유독 많다.
- **근거**: 온보딩 퍼널 데이터를 확인했다.

> **판단 이유**: 퍼널 데이터에서 특정 단계의 이탈이 많다는 관찰 결과를 확인했으므로 학습으로 분류했다.

## [가정] 실제 결제 계정은 다음 주에 발급될 가능성

- **가설**: 실제 결제 계정은 다음 주에나 나올 것으로 보인다.

> **판단 이유**: 실제 계정 발급 시점에 대해 '것 같음'이라고 추정한 미확인 상태의 사실 판단이므로 가정이다.

## [가정] 온보딩 3단계 이탈의 원인은 UX 문제일 가능성

- **가설**: 온보딩 3단계의 높은 이탈은 UX 문제일 것이라고 보고 있다.
- **근거**: 온보딩 퍼널 데이터에서 3단계 이탈이 유독 많았다.

> **판단 이유**: 원인은 아직 정확히 모른다고 명시하면서 UX를 원인으로 추정했으므로, 확정된 학습이 아닌 가정으로 분류했다.

## 제외된 판단 (4개)

- "오늘 이미지 OCR 기능을 마저 붙일 예정" — 향후 실행할 작업일 뿐, 왜 이 방식을 택했는지 되짚을 수 있는 판단이 아니다.
- "테스트 커버리지를 늘리는 중이며 특이사항 없음" — 진행 상태 보고로, 독립적인 결정·미결 사항·확인된 학습을 담고 있지 않다.
- "디자인 시스템 컴포넌트 3개 마무리" — 완료된 작업의 상태 보고이며, 후속 작업 우선순위에 관한 미결 판단은 별도 pending으로 기록했다.
- "인프라 쪽 특이사항 없음" — 단순 상태 보고로 독립적인 판단이 아니다.
