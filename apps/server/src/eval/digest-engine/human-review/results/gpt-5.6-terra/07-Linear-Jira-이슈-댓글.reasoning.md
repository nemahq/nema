## [결정] 알림 배지 버그를 이번 스프린트에 수정하고 High 우선순위를 유지

- **상황**: 버그의 발생 빈도와 심각도를 다시 평가할 필요가 있었다.
- **선택**: 알림 배지 카운트 불일치를 이번 스프린트 안에 수정하고 우선순위는 High로 유지한다.
- **이유**: 로그상 하루 약 40건으로 활성 사용자 대비 비중은 크지 않지만, 한 번 발생하면 새로고침 전까지 잘못된 카운트가 계속 표시되어 체감 영향이 클 것으로 보였다.

> **판단 이유**: PM이 발생 빈도와 심각도 재평가를 요청한 뒤, 재윤이 로그 기반 빈도와 지속 영향을 공유했고 하윤이 이번 스프린트 수정 및 High 유지를 명시했다.

## [결정] 배지 갱신에서 낙관적 업데이트 제거

- **상황**: 낙관적 업데이트를 없앨지, 유지한 채 타이밍 버그만 수정할지 결정해야 했다.
- **선택**: 낙관적 업데이트를 제거하고 서버 응답을 기준으로만 알림 배지를 갱신한다.
- **이유**: 사용자 입장에서는 배지가 잘못 표시되는 것보다 약 0.5초 느리게 반응하는 편이 낫다는 디자인 의견을 반영했다.
- **트레이드오프**: 
  - 배지 반응이 약 0.5초 느리게 느껴질 수 있다.
- **대안**: 
  - 낙관적 업데이트는 유지하고 타이밍 버그만 수정 — 낙관적 업데이트를 유지하면 배지가 잘못된 값을 보일 위험이 있으며, 사용자에게는 이 문제가 반응 지연보다 더 나쁘다고 판단했다.

> **판단 이유**: 재윤이 두 구현 방향을 비교한 뒤 디자인 의견을 반영해 서버 응답만 사용하는 방향으로 하기로 했다고 명시했다.

## [미결] 알림 목록 API 페이지네이션 문제의 별도 티켓 생성 여부

- **질문**: 알림 목록 API의 페이지네이션 처리 문제를 별도 티켓으로 만들지 결정하지 못했다.
- **배경**: 수정 작업 중 알림 목록 API의 페이지네이션 처리도 이상하다는 점을 발견했지만, 현재 알림 배지 버그 이슈의 범위는 아닌 것으로 보였다.
- **선택지**: 
  - 별도 티켓 생성

> **판단 이유**: 재윤이 페이지네이션 문제를 발견했으나 별도 티켓을 만들지 아직 결정하지 않았다고 밝혔으므로, 미결정 사안으로 분류했다.

## [학습] 알림 배지 불일치는 하루 약 40건 발생

- **발견**: 로그상 알림 배지 카운트 불일치는 하루에 대략 40건 발생한다.
- **근거**: 재윤이 로그를 확인했다.

> **판단 이유**: 로그 확인 결과로 발생 빈도가 제시되어 있어 확인된 사실로 분류했다.

## [학습] 로컬 재현 시나리오 20회에서 이상 없음

- **발견**: PR #1204의 변경 사항은 로컬 재현 시나리오를 20회 실행했을 때 이상이 없었다.
- **근거**: 재윤이 로컬에서 재현 시나리오를 20번 실행해 확인했다.

> **판단 이유**: 재윤이 수행한 반복 테스트의 결과를 확인했다고 명시했으므로 학습으로 포함했다.

## [가정] 낙관적 업데이트와 서버 응답 간 타이밍 문제가 불일치 원인일 수 있음

- **가설**: 클라이언트가 배지 카운트를 낙관적으로 증가시킨 뒤 서버 응답의 실제 값으로 덮어쓰는 타이밍이 누락되는 것이 문제 원인일 수 있다.
- **근거**: 재윤이 버그를 재현했다.

> **판단 이유**: 재윤이 원인으로 추정했지만 '확실친 않습니다'라고 명시했으므로, 검증되지 않은 원인 가설인 가정으로 분류했다.
