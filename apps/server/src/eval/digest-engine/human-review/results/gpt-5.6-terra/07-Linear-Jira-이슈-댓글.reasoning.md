## [결정] 알림 배지 버그를 이번 스프린트 내 수정하고 High 우선순위를 유지

- **상황**: 발생 빈도와 사용자 체감 심각도를 기준으로 이슈의 대응 시점과 우선순위를 재검토해야 했다.
- **선택**: 알림 배지 카운트 불일치 버그를 이번 스프린트 안에 수정하며 우선순위는 High로 유지한다.
- **이유**: 활성 사용자 대비 발생 건수는 크지 않지만, 한 번 발생하면 새로고침 전까지 계속 잘못된 카운트가 보여 사용자 체감 영향이 클 것으로 보였다.

> **판단 이유**: 하윤이 발생 빈도와 심각도를 다시 보려 했고, 이후 이번 스프린트 수정 및 High 유지라는 대응 방침을 확정했다.

## [결정] 낙관적 배지 업데이트를 제거하고 서버 응답 기준으로 갱신

- **상황**: 배지 카운트 불일치를 고치기 위해 낙관적 업데이트를 없앨지, 타이밍 버그만 수정할지 결정해야 했다.
- **선택**: 클라이언트의 낙관적 업데이트를 제거하고 서버 응답 값만으로 알림 배지를 갱신한다.
- **이유**: 사용자 관점에서는 배지가 틀린 것보다 반응이 약간 느린 편이 낫다는 디자인 의견을 반영했다.
- **트레이드오프**: 
  - 배지 반응이 약 0.5초 느리게 느껴질 수 있다.
- **대안**: 
  - 낙관적 업데이트는 유지한 채 타이밍 버그만 수정한다.

> **판단 이유**: 재윤이 두 구현 방향을 비교한 뒤, 소영의 의견을 반영해 낙관적 업데이트 제거를 최종 결정했다고 명시했다.

## [미결] 알림 목록 API 페이지네이션 문제를 별도 티켓으로 만들지 결정 필요

- **질문**: 알림 목록 API의 페이지네이션 처리 문제를 별도 티켓으로 등록할지 결정해야 한다.
- **배경**: 배지 버그를 수정하는 과정에서 알림 목록 API의 페이지네이션 처리도 이상한 점이 발견됐지만, 현재 이슈의 범위는 아닌 것으로 보였다.
- **선택지**: 
  - 별도 티켓을 등록한다.
  - 별도 티켓을 아직 등록하지 않는다.

> **판단 이유**: 재윤이 페이지네이션 문제의 별도 티켓 생성 여부를 아직 결정하지 않았다고 밝혔다.

## [학습] 배지 카운트 불일치가 재현되며 새로고침 후 정상화됨

- **발견**: 사이드바 알림 배지가 실제 미확인 항목 수보다 크게 표시되는 문제가 재현되며, 새로고침하면 카운트가 다시 실제 값과 일치한다.
- **근거**: 배지에는 5가 표시되지만 실제 미확인 항목은 2개인 사례가 재현됐다.

> **판단 이유**: 이슈 설명과 재윤의 재현 보고는 배지 불일치 및 새로고침 후 정상화라는 관찰된 동작을 확인된 사실로 제시한다.

## [학습] 배지 카운트 불일치는 하루 약 40건 발생

- **발견**: 로그상 배지 카운트 불일치는 하루에 대략 40건 발생한다.
- **근거**: 재윤이 로그를 확인해 하루 약 40건이 기록된다고 보고했다.

> **판단 이유**: 로그 확인 결과를 근거로 발생 빈도가 구체적으로 보고됐으므로 확인된 발견으로 분류했다.

## [학습] 수정 PR의 로컬 재현 시나리오 테스트가 20회 통과

- **발견**: PR #1204는 로컬 재현 시나리오를 20회 실행했을 때 이상이 없었다.
- **근거**: 재윤이 로컬에서 재현 시나리오를 20번 돌려 확인했다고 보고했다.

> **판단 이유**: PR 검증 과정에서 얻은 테스트 결과를 확인된 사실로 보고한 내용이다.

## [가정] 낙관적 업데이트와 서버 응답 처리 타이밍이 불일치 원인일 수 있음

- **가설**: 클라이언트가 배지 카운트를 낙관적으로 증가시킨 뒤 서버 응답의 실제 값으로 덮어써야 하는 시점이 누락되는 것이 불일치의 원인일 수 있다.
- **근거**: 재윤이 해당 흐름을 원인으로 추정했지만 확실하지 않다고 밝혔다.

> **판단 이유**: 원인에 대한 설명이지만 재윤이 '확실친 않다'고 명시했으므로, 검증되지 않은 상태 설명인 가정으로 분류했다.

## 제외된 판단 (2개)

- "PR #1204를 오늘 중으로 올리겠다는 언급 및 실제 PR 등록" — PR 작성·등록은 실행 상태와 작업 완료 보고이며, 향후 왜 그렇게 했는지를 물을 판단 자체가 아니다.
- "이슈 상태가 In Progress이고 담당자가 재윤이라는 메타데이터" — 상태와 담당자 표기는 이슈 관리 정보일 뿐 판단을 담고 있지 않다.
