## 원문 제목

NEMA-482 알림 배지 카운트 불일치 원인 및 수정 방향

> **판단 이유**: 노트 전체가 알림 배지의 실제 미확인 수 불일치 현상, 우선순위 판단, 수정 방식, 그리고 발견된 별도 API 문제를 다룬다. 특정 결정 하나가 아니라 이 이슈의 조사와 대응 전반을 포괄하는 제목이다.

## [결정] 버그 우선순위를 High로 유지

- **상황**: 발생 빈도를 확인한 뒤 이슈의 심각도를 다시 판단해야 했다.
- **선택**: 알림 배지 카운트 불일치 버그의 우선순위를 High로 유지한다.
- **이유**: 로그상 하루 약 40건 발생하며, 한 번 발생하면 새로고침 전까지 잘못된 값이 계속 표시된다.

> **판단 이유**: PM이 발생 빈도와 심각도를 재검토하려 했고, 확인된 발생 양상 후 우선순위를 그대로 High로 유지한다고 명시했다.

## [결정] 이번 스프린트 내 알림 배지 버그 수정

- **상황**: 발생 빈도와 사용자 체감 영향을 바탕으로 수정 시점을 정해야 했다.
- **선택**: 알림 배지 카운트 불일치 버그를 이번 스프린트 안에 수정한다.
- **이유**: 로그상 하루 약 40건 발생하고, 오류가 발생하면 새로고침 전까지 잘못된 카운트가 유지된다.

> **판단 이유**: PM이 발생 규모를 들은 뒤 '이번 스프린트 안에 고치는 걸로' 결정했다. 우선순위 유지와는 별개로 수정 일정을 정한 판단이다.

## [결정] 서버 응답 기준으로만 배지 카운트 갱신

- **상황**: 낙관적 업데이트를 완전히 없앨지, 이를 유지한 채 타이밍 버그만 수정할지 결정해야 했다.
- **선택**: 낙관적 업데이트를 제거하고 서버 응답 기준으로만 알림 배지 카운트를 갱신한다.
- **이유**: 사용자 관점에서는 배지가 틀리는 것보다 반응이 0.5초 느린 편이 낫다는 디자인 의견을 반영했다.
- **트레이드오프**: 
  - 배지 반응이 약 0.5초 느려져 둔하게 느껴질 수 있다.
- **대안**: 
  - 낙관적 업데이트를 유지하고 타이밍 버그만 수정

> **판단 이유**: 재윤이 두 구현 방향을 검토한 뒤, 디자인 의견을 반영해 낙관적 업데이트 제거를 최종 결정했다고 밝혔다.

## [미결] 알림 목록 API 페이지네이션 문제의 별도 티켓 생성 여부

- **질문**: 알림 목록 API의 페이지네이션 처리 문제를 별도 티켓으로 등록할지 결정해야 한다.
- **배경**: 배지 버그를 수정하는 과정에서 알림 목록 API의 페이지네이션 처리도 이상해 보였지만, 현재 이슈 범위에는 포함되지 않는 것으로 보인다.
- **선택지**: 
  - 별도 티켓을 생성 — 페이지네이션 처리 문제는 현재 배지 카운트 버그 이슈의 범위가 아닌 것으로 보인다.
  - 별도 티켓을 생성하지 않음

> **판단 이유**: 재윤이 페이지네이션 문제를 발견했지만 별도 티켓을 만들지는 아직 정하지 않았다고 명시했으므로, 해결되지 않은 결정 사항이다.

## [학습] 알림 배지와 실제 미확인 수의 불일치 재현

- **발견**: 사이드바 알림 배지가 실제 미확인 항목 수보다 크게 표시되는 현상이 재현되며, 새로고침하면 카운트가 다시 맞는다.
- **근거**: 배지에 5가 표시될 때 실제 미확인 항목은 2개였고, 재윤이 해당 현상을 재현했다.

> **판단 이유**: 이슈 설명과 재윤의 재현 확인은 현상의 존재와 새로고침 후 정상화 여부를 확인된 사실로 제시한다.

## [학습] 버그 발생 빈도와 지속성 확인

- **발견**: 알림 배지 카운트 불일치 오류는 로그상 하루에 약 40건 발생하며, 발생 후 새로고침 전까지 잘못된 값이 표시된다.
- **근거**: 재윤이 로그에서 하루 약 40건을 확인했고, 오류가 나면 새로고침 전까지 계속 틀린 값이 보인다고 보고했다.

> **판단 이유**: 로그 확인 결과와 오류가 지속되는 동작이 구체적으로 보고되어, 발생 규모와 사용자 노출 양상에 관한 확인된 정보다.

## [학습] 로컬 재현 시나리오 20회에서 이상 없음

- **발견**: PR #1204의 변경 사항은 로컬 재현 시나리오를 20회 실행했을 때 이상이 없었다.
- **근거**: 재윤이 로컬에서 재현 시나리오를 20번 돌려 확인했다고 보고했다.

> **판단 이유**: 재윤이 반복 실행 결과 이상이 없었다고 명시했으므로, 로컬 검증 결과에 관한 학습으로 분류했다.

## [가정] 낙관적 업데이트 타이밍이 배지 불일치의 원인일 수 있음

- **가설**: 클라이언트가 배지 카운트를 낙관적으로 증가시킨 뒤 서버 응답의 실제 값으로 덮어써야 하는 타이밍이 누락되는 것이 불일치의 원인일 수 있다.
- **근거**: 재윤이 재현 후 클라이언트의 낙관적 증가와 서버 응답 덮어쓰기 흐름을 원인으로 추정했다.

> **판단 이유**: 재윤이 '원인은 이거 같은데 확실친 않다'고 명시했으므로, 검증되지 않은 원인 가설인 가정으로 분류했다.

## 제외된 판단 (3개)

- "낙관적 업데이트를 없앨지, 타이밍 버그만 잡을지 고민 중이라는 초기 언급" — 이후 서버 응답 기준 갱신으로 최종 결론이 났으며, 검토한 경로는 해당 결정의 대안으로 통합했다.
- "소영의 ‘배지가 틀린 것보다 0.5초 느린 게 낫다’는 의견" — 독립적인 판단이 아니라 낙관적 업데이트 제거 결정의 이유와 감수한 비용으로 통합했다.
- "오늘 중 PR을 올리겠다는 계획과 PR #1204를 올렸다는 보고" — 완료 예정 또는 완료된 작업 상태 보고로, 나중에 왜 그렇게 했는지를 물을 수 있는 판단이 아니다.
