## [결정] 알림 배지 갱신 방식 변경

- **상황**: 알림 배지 카운트와 실제 미확인 수 불일치 문제를 해결하기 위해, 낙관적 업데이트를 유지하며 타이밍 오류를 고칠지 아니면 삭제할지 고민함
- **선택**: 낙관적 업데이트를 제거하고 서버 응답 기준으로만 배지를 갱신함
- **이유**: 사용자 입장에서 정확하지 않은 배지보다는 약간의 반응 지연이 낫다는 디자인 팀의 의견을 수용함
- **트레이드오프**: 
  - 배지가 반응하는 속도가 둔해짐
- **대안**: 
  - 낙관적 업데이트를 유지하면서 타이밍 오류만 수정

> **판단 이유**: 재윤과 소영의 논의를 통해 낙관적 업데이트 제거라는 최종 결정이 내려졌으므로 이를 결정으로 분류함.

## [미결] 알림 목록 API 페이지네이션 문제 처리 여부

- **질문**: 알림 목록 API 페이지네이션 오류를 별도 티켓으로 관리할 것인가?
- **배경**: 알림 배지 이슈 수정 과정에서 알림 목록 API의 페이지네이션 처리가 이상하다는 것을 발견함
- **선택지**: 
  - 별도 티켓을 생성하여 관리한다
  - 현재 티켓에 포함시키거나 별도의 조치를 취하지 않는다
- **확인 조건**: 재윤 혹은 관련 담당자가 별도 티켓 생성 여부를 결정함

> **판단 이유**: 이 문제가 발견되었으나 아직 티켓을 팔지 여부가 미정이라고 명시되어 있음.

## [학습] 알림 배지 카운트 불일치 원인 확인

- **발견**: 클라이언트의 낙관적 업데이트와 서버 응답 처리 타이밍 사이의 충돌로 인해 배지 카운트가 틀려짐
- **근거**: 재윤이 로컬 재현 시나리오 및 로그를 통해 확인

> **판단 이유**: 원인이 확인되었고 재현 시나리오를 통해 검증되었으므로 학습으로 분류함.
