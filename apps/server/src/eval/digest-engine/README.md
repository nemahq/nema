# digest-engine eval

원문 → 다이제스트(정리) 단계의 프롬프트 품질을 실제 원문으로 확인하는 자리. 몫은 정리까지다.
진술 추출·관계 판정·연결("잇기")은 각자 다른 파이프라인 단계라(`organizing.md` vs `linking.md`가
별개 챕터인 것과 같은 이유) 여기 몫이 아니고, 나중에 `statement-engine/`·`relation-engine/`이
생기면 그쪽 몫이다.

## 원문 성격을 보는 4축

포맷(Slack·회의노트·Linear 댓글·AI 세션 로그 …)과는 다른 축이다. 포맷은 "어디서 캡처됐나"고,
아래 넷은 "왜/어떻게 판단이 생겼나"다. 같은 포맷도 이 축에 따라 완전히 다른 신호를 낸다.

1. **목적/부산물**: 이 대화 자체가 결정하려고 소집됐나(목적형), 다른 목적으로 모였다가 판단이
   곁가지로 남았나(부산물형). 둘 다 필요하다 — 부산물형은 아무도 안 적었을 걸 캡처하는
   값어치고, 목적형은 "의식적으로 정리해야지" 싶은 순간에 Nema를 떠올려 그 자리로 쓰는
   값어치다(self-interview가 짚은 "판단을 brain 문서로 압축"하던 습관이 정확히 이 두 번째다).
   값어치가 다를 뿐 어느 한쪽이 더 크지 않다.
2. **불확실성의 형태**: 확정(decision) / 탐색(pending·idea) / 암묵(assumption, 누구도 확인
   안 했지만 다들 그렇다고 가정하며 진행).
3. **참여자 구도**: 혼자 / 1:1 / 소그룹 / 외부개입(고객·투자자·파트너).
4. **트리거**: 계획된 논의 / 외부 자극 반응(고객 이탈·장애·경쟁사 움직임) / 회고·재평가.

## 테스트 케이스 11종

원문은 첫 대상(1~20인 스타트업 창업자·PM, AI를 업무에 깊게 쓰고 하루에도 여러 번 판단을
내리는 사람)이 실제로 만들 법한 원문에 가깝게, 민감정보를 뺐거나 실제 패턴을 본뜬 가상
데이터로 채운다(`samples/`).

**표는 여기서 규모를 고정한다.** 합성 케이스는 회귀 방지용이지 발견용이 아니다 — 이미 예측
가능한 리스크만 잡는다. 이후 추가는 실사용에서 실제로 걸린 사례가 나올 때만 한다(아래
"평가 방식" 참고).

## 평가 방식

**환경은 staging이다**(로컬 Supabase는 워크트리 공유 스택이라 `db reset`마다 데이터가
날아간다). 도그푸딩 계정(`claude@getnema.app`)이 이 용도로 격리돼 있어 실사용 데이터와
안 섞인다.

지금은 **사람이 눈으로 본다**(`human-review/`). 아직 "무엇이 좋은 다이제스트인가"의 기준이
안 잡혀서, LLM 자동 채점(`llm-eval/`)을 먼저 만들면 검증 안 된 가정을 채점 기준에 미리
박아넣게 된다. 사람 리뷰를 몇 바퀴 돌려 기준이 잡히면 그때 `llm-eval/`을 채운다.

합성 케이스로 볼 것은 4가지다. 초기 논의에서 짚은 3가지, 실데이터에서만 보이는 것 1가지:

1. 다섯 유형 비율, 특히 assumption이 잡히는지
2. pending vs idea가 실제로 갈리는지
3. 칸이 얼마나 비는지(원문에 없는 것만 비어야 함)
4. "이미 정해진 걸 재확인만 한 문장"과 "이번에 새로 나온 판단"을 구분하는지

### 실사용(dogfooding) 신호 — 여기가 주력이다

합성 케이스는 예측 가능한 리스크만 잡는다. 못 예측한 실패는 실제로 써봐야 나온다. Nema를
자기 메모에 실제로 써보면서 볼 것:

- **"아이디어 좋네요"가 아니라 "이전 방식(brain)으로 돌아가기 싫다"가 신호다.** 다이제스트가
  괜찮아 보이는지보다, 넣기 전에 "brain에 쓸까 Nema에 쓸까" 고민하는 순간 자체가 데이터다.
- **안 쓴 순간을 기록한다.** "이 메모는 지저분해서 그냥 안 넣었다"는 회피는 합성 테스트로
  못 잡는 실패다. 안 넣은 이유가 다음 케이스가 된다.
- **며칠 뒤 다시 읽었을 때가 진짜 시험이다.** 방금 만든 건 원문이 머릿속에 있어 평가가 후하다.
  맥락 없이 다시 열었을 때 "내가 쓴 거 맞나" 싶으면 실패 신호다.
- **마찰 자체를 Nema에 적는다.** 별도 로그 없이, "오늘 이런 게 별로였다"는 메모 자체가
  판단(assumption·learning)이라 재귀적으로 다이제스트가 된다.
