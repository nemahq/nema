# B2B 마케팅 자동화 로드맵 정리 — 4월 3주차

참석: 지훈(PM), 라희(디자인), 성민(엔지니어), 도경(엔지니어)

### 리드 업로드 방식 전환

- 기존 CSV 업로드는 유저/리드 분리, 필드 매핑, 옵션 설정 과정이 길고 무거워서 실제로 잘 안 쓰이고 있었다.
- 테이블 형태 데이터는 붙여넣기만 해도 웬만큼 자동 인식이 가능하다는 걸 확인했다.
- 확장성을 고려해 CSV 업로드 대신 복사-붙여넣기 방식을 우선 채택하기로 했다. 매핑과 기본 키 검증 정도만 남기고 나머지는 가볍게 간다.

### 이벤트 트리거 방식

- 초반엔 모든 이벤트를 자연어로 필터링하는 걸 검토했는데, 월 이벤트가 1~2억 건 규모로 나와서 전부 LLM에 태우면 서버 비용이 감당이 안 된다는 게 이번에 확인됐다.
- 그래서 트리거는 룰베이스로 먼저 걸러서 물량을 1% 수준(150만 건 이하)까지 줄인 다음에만 LLM을 적용하기로 결정했다. 자연어 입력은 룰을 만드는 과정에서 보조적으로만 쓴다.

### 이번 스프린트 우선순위

- B2B 리드젠에 필요한 컨텐츠 파트(캠페인 자료 구성)를 가장 먼저 개발하기로 했다. 정해진 시간에 자동으로 보내는 기능은 나중으로 미룬다 — 컨텐츠 파트가 핵심이고 시간 지정은 천천히 만들어도 된다는 데 다들 동의했다.

### 대시보드 정보량

- 대시보드에는 캠페인 성과 요약 정도만 보여주고, 세부 데이터는 별도 리포트 화면에서 확인하는 걸로 정리했다. 처음엔 대시보드에 상세 지표까지 다 넣자는 의견도 있었는데, 화면이 복잡해진다는 우려에 밀렸다.

### 발신 채널 배치 — 결론 못 냄

- 전화·문자 등 발신 채널을 오디언스 설정에 넣을지, 발송 기준 쪽에 넣을지, 아니면 별도 운영 화면으로 뺄지 의견이 갈렸다. 오디언스에 넣으면 연락처 입력이 자연스럽게 유도된다는 장점은 있는데, 그러면 오디언스 설정이 너무 무거워질 수 있다는 반론도 있었다. 결론은 다음 회의로 넘겼다.

### 캠페인 스키마 생성 방식 — 이번 주 안에 결론 내기로

- 캠페인 만들 때 필요한 항목(입력 스키마)을 LLM이 자동으로 만들게 할지, 아니면 정해진 함수 호출로 고정된 스키마를 쓰게 할지 아직 못 정했다. LLM 자동 생성이 유연하긴 한데 안정성이 검증 안 됐다는 게 걸림돌이다. 성민과 도경이 이번 주 안에 어느 쪽으로 갈지 정하기로 했다.
