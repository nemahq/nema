## 1. [결정] 성공률 기준 수립

- **상황**: 테스트 성공률이 기대보다 낮게 나오는 이슈가 발생함.
- **선택**: 단순 동작은 100% 통과, 복잡한 동작은 10번 중 9번 이상 통과를 목표로 함.
- **이유**: 단순 로직에서조차 낮은 성공률이 확인되어 명확한 품질 기준이 필요했음.

**statement**: 성공률 기준은 단순 동작 100% 통과, 복잡한 동작은 10번 중 9번 이상 통과로 결정되었다.

## 2. [결정] 회귀 테스트 의무화

- **상황**: 프롬프트 수정 이후 배포 단계에서 기존 이슈가 재발하는 경우가 있었음.
- **선택**: 프롬프트 수정 후 기존 회귀 테스트를 전부 통과해야만 배포.
- **이유**: 이전 배포 프로세스가 느슨했던 점을 보완하기 위함.
- **트레이드오프**: 
  - 배포 속도 저하

**statement**: 회귀 테스트를 전부 통과해야만 프롬프트 수정 이후 배포를 할 수 있도록 결정되었다.

## 3. [미결] 에이전트 아키텍처 구조 결정

- **질문**: 단일 에이전트 구조를 유지할지, 서브/루트 에이전트로 역할을 쪼갤지 여부.
- **배경**: 현재 구조로는 루트 에이전트가 서브 에이전트의 지식을 공유받지 못하는 한계가 있음.
- **선택지**: 
  - 단일 에이전트 체제 유지
  - 서브/루트 에이전트 분리 및 지식 공유 구조 설계
- **확인 조건**: 별도의 회의를 통해 구조적 한계 해결 방안 논의 및 결정.

**statement**: 에이전트 아키텍처 구조를 단일 체제로 유지할지 서브 및 루트 에이전트로 역할을 쪼갤지에 대한 여부는 미결정 상태이다.

## 4. [학습] LLM 동작 복잡도와 성공률의 비례성 부재

- **발견**: 단순해 보이는 동작도 LLM 기반 프롬프트에서는 성공률이 낮게 나타날 수 있음.
- **근거**: 삭제 호출 여부 판단이라는 단순 로직이 60~80%의 성공률을 기록함.

**statement**: LLM 기반 프롬프트에서는 단순한 동작이라도 성공률이 낮게 나타날 수 있다는 사실이 확인되었다.

## 5. [학습] LLM 응답의 랜덤성 검증을 위한 반복 실행 필수화

- **발견**: LLM 응답의 일관성을 확인하려면 단일 검증이 아닌 반복 테스트가 필수임.
- **근거**: 한 번 통과했던 테스트도 반복 실행 시 결과가 매번 달라짐을 확인.

**statement**: LLM 응답의 일관성을 확인하기 위해서는 단일 검증이 아닌 반복 테스트가 필수적이다.

## 6. [학습] 테스트 방식 전환의 효율성

- **발견**: 수동 시스템 프롬프트 검토보다 리플레이 방식의 테스트가 효율적임.
- **근거**: 리플레이 기능 도입 후 작업 과정이 크게 단축됨.

**statement**: 리플레이 방식의 테스트가 수동 시스템 프롬프트 검토보다 효율적이다.

## 7. [학습] 자동화 도구 제안의 한계

- **발견**: LLM 자동 개선 제안을 검토 없이 적용해서는 안 됨.
- **근거**: 제안대로 수정했다가 기존 사례가 깨지는 현상 발생.

**statement**: 자동화 도구의 LLM 자동 개선 제안은 검토 없이 적용해서는 안 된다.
