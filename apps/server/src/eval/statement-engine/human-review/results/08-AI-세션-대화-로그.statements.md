## 1. [결정] 캐시 무효화 전략 결정

- **상황**: 캐시 무효화 전략으로 TTL 방식과 이벤트 기반 무효화 방식 사이에서 고민 중임
- **선택**: TTL 30초 설정 및 이벤트 기반 무효화는 추후 도입
- **이유**: 현재 리소스로 이벤트 기반의 복잡도를 감당하기 부담스러워 절충안을 선택함
- **트레이드오프**: 
  - 구현 복잡도를 낮추는 대신 짧은 기간 동안 오래된 데이터가 노출될 수 있음
- **대안**: 
  - TTL 방식만 적용(기존)
  - 이벤트 기반 무효화 구현

**statement**: 캐시 무효화 전략으로 TTL 30초 설정을 채택하고 이벤트 기반 무효화는 추후 도입하기로 결정되었다.

## 2. [미결] 캐시 키에 사용자 ID 포함 여부

- **질문**: 캐시 키 구조에 지금 유저 ID를 미리 포함할 것인가?
- **배경**: 향후 사용자별로 다른 데이터를 보여주는 기능 도입 가능성이 있어 캐시 키 변경이 필요할 수 있음
- **선택지**: 
  - 지금 미리 유저 ID를 포함
  - 필요할 때 나중에 반영
- **확인 조건**: 사용자별 데이터 노출 기능 도입이 확정될 때

**statement**: 캐시 키 구조에 사용자 ID를 미리 포함할지 여부는 아직 결정되지 않았다.
