## 1. [결정] 리드 업로드 방식을 복사-붙여넣기로 변경

- **상황**: 기존 CSV 업로드 방식은 유저와 리드 분리, 필드 매핑 등 과정이 복잡하여 사용자 활용도가 낮았음.
- **선택**: CSV 업로드 대신 복사-붙여넣기 방식을 채택함.
- **이유**: 테이블 형태 데이터는 붙여넣기만으로도 충분히 자동 인식이 가능하며, 확장성을 고려할 때 더 효율적임.
- **트레이드오프**: 
  - 기존 CSV 기능의 복잡한 옵션 설정 제거
  - 매핑과 기본 키 검증 기능만 최소화하여 구현

**statement**: 리드 업로드 방식으로 CSV 업로드 대신 복사-붙여넣기 방식이 채택되었다.

## 2. [결정] 이벤트 트리거 방식에 룰베이스 선적용 결정

- **상황**: 전체 이벤트를 LLM으로 처리할 경우 서버 비용이 감당하기 어려운 수준임.
- **선택**: LLM을 사용하기 전 룰베이스로 이벤트를 1% 수준으로 필터링하기로 함.
- **이유**: 필터링을 통해 처리량을 150만 건 이하로 줄여야 비용 효율성을 확보할 수 있음.
- **트레이드오프**: 
  - 자연어 입력은 룰 생성 보조 도구로만 사용
  - LLM 적용 범위 축소
- **대안**: 
  - 모든 이벤트를 자연어로 필터링하는 방식

**statement**: 이벤트 트리거 방식에서 LLM을 사용하기 전 룰베이스로 이벤트를 1% 수준으로 필터링하는 방안이 결정되었다.

## 3. [결정] 스프린트 우선순위로 컨텐츠 파트 선정

- **상황**: 스프린트 내 개발 우선순위를 결정해야 함.
- **선택**: B2B 리드젠 컨텐츠 파트를 우선 개발하고, 자동 발송 기능은 후순위로 미룸.
- **이유**: 컨텐츠 파트가 핵심 기능이며, 시간 지정 발송은 추후 구현해도 충분함.

**statement**: 스프린트 우선순위로 B2B 리드젠 컨텐츠 파트가 선정되고 자동 발송 기능은 후순위로 미뤄졌다.

## 4. [결정] 대시보드 성과 요약 위주 구성

- **상황**: 대시보드에 담을 정보량을 결정해야 함.
- **선택**: 대시보드에는 캠페인 성과 요약만 표시하고 상세 데이터는 별도 화면으로 분리함.
- **이유**: 상세 지표까지 모두 넣을 경우 화면이 지나치게 복잡해질 우려가 있음.
- **트레이드오프**: 
  - 사용자가 상세 데이터를 보려면 추가 화면으로 이동해야 함
- **대안**: 
  - 대시보드에 상세 지표까지 모두 포함

**statement**: 대시보드에는 캠페인 성과 요약 정보만 표시하고 상세 데이터는 별도 화면으로 분리하기로 결정되었다.

## 5. [미결] 발신 채널 배치 전략

- **질문**: 전화·문자 등 발신 채널을 오디언스 설정, 발송 기준, 혹은 별도 운영 화면 중 어디에 배치할 것인가?
- **배경**: 오디언스 설정에 넣을 경우 연락처 유도는 쉽지만 설정이 무거워질 수 있다는 의견 대립이 있음.
- **선택지**: 
  - 오디언스 설정에 포함
  - 발송 기준에 포함
  - 별도 운영 화면으로 분리
- **확인 조건**: 다음 회의에서 결론을 내기로 함.

**statement**: 발신 채널 배치 전략에서 전화 및 문자 등 발신 채널을 오디언스 설정과 발송 기준 혹은 별도 운영 화면 중 어디에 배치할지는 아직 결정되지 않았다.

## 6. [미결] 캠페인 스키마 생성 방식 결정

- **질문**: 입력 스키마를 LLM이 자동 생성하게 할 것인가, 고정된 함수 호출을 사용할 것인가?
- **배경**: 자동 생성은 유연하지만 안정성이 검증되지 않았고, 함수 호출은 고정된 방식을 사용해야 함.
- **선택지**: 
  - LLM 자동 생성
  - 고정된 함수 호출 사용
- **확인 조건**: 성민과 도경이 이번 주 안에 결론을 내기로 함.

**statement**: 캠페인 스키마 생성 방식에 있어 입력 스키마를 LLM이 자동 생성하게 할 것인지 또는 고정된 함수 호출을 사용할 것인지는 결정되지 않았다.

## 7. [학습] CSV 업로드 방식의 비효율성 확인

- **발견**: CSV 업로드 기능은 사용자 활용도가 낮음.
- **근거**: 유저/리드 분리, 필드 매핑 등 과정이 길고 무거움.

**statement**: CSV 업로드 기능은 사용자 활용도가 낮다.

## 8. [학습] 테이블 데이터의 붙여넣기 인식 가능성

- **발견**: 테이블 형태 데이터는 복사-붙여넣기만으로도 자동 인식이 가능함.
- **근거**: 테스트를 통해 붙여넣기 시 웬만큼 자동 인식이 됨을 확인함.

**statement**: 테이블 형태의 데이터는 복사 후 붙여넣기만으로도 자동 인식이 가능하다.

## 9. [학습] LLM 전체 적용 시 비용 문제

- **발견**: 월 1~2억 건 규모의 이벤트를 전부 LLM으로 처리하기에는 서버 비용이 너무 큼.
- **근거**: 전부 LLM에 태우는 방식을 검토한 결과 비용 감당이 안 됨을 확인함.

**statement**: 월 1에서 2억 건 규모의 이벤트를 전부 대규모 언어 모델로 처리하기에는 서버 비용이 너무 많이 발생한다.
